# FEAT-023 — known bugs

*One line per known bug in this feature, moved from HANDOFF.md on 2026-10-21 and kept word for word. A review finding that does not block a land goes here as one line.*

- Roster notice: nobody has looked at the notice in either app yet. pi's panel stays until the next reset and wraps at 80 columns. A relative agent folder shows "roster unknown". Two providers that serve one model name look the same in it. The Windows-only hook checks run only in CI's Windows leg. On a case-sensitive macOS volume, a path spelled in another letter case still shows as `~`.
- Compaction journal lines (lifecycle-compaction-reason, plan and independent check): a reason that is not text goes into the journal as pi gave it. A reason JSON cannot write, such as a big integer, drops that whole line with no warning. Compaction still goes on. The threat model leaves such reasons out.
- Compaction journal lines (lifecycle-compaction-reason, plan and independent check): the journal keeps only the reason from pi's compaction events. Whether pi will retry, whether it aborted, the error text and whether an extension started it stay out. Journaling any of them means changing the requirement that lists a compaction line's fields.
- Compaction journal lines (lifecycle-compaction-reason, plan and independent check): pi versions 0.74 to 0.79.9 send compaction events with no reason. The journal then writes each line with no reason field, and a check pins that. The independent check sent that shape through pi 1.0.2's runner only. Nobody has tested whether the pack loads on any pi older than 1.0.2.
- Windows toast (notify-lifecycle-pins plan): the toast names pi as its app, but no Start menu entry registers that name. Current Windows may then drop the toast with no error, so neither the toast nor the fallback shows (inferred, not run). CI cannot see a toast. The plan lists four owner steps in a Windows PowerShell window that would settle it.
- Notify checks (notify-lifecycle-pins plan): the new checks prove the command the notify extension builds. They do not prove that the system shows a notice.
- Notify checks (notify-lifecycle-pins plan): an older headless check pairs terminal mode with no screen. pi 1.0.2 never binds that pair, though a program embedding pi could. That check expects an escape code, which the no-escape-code requirement forbids.
- Notify checks (notify-lifecycle-pins plan): four older approval-prompt checks print into the output they capture. So a failure there prints no failure line. The run still exits non-zero.
- Notify checks (notify-lifecycle-pins, final review): the notify tests' platform helper restores the real platform as soon as its callback returns a promise. So the fake platform covers only the synchronous start of the handler that runs when the agent settles. This weakens the test, not the product.
- Lifecycle journal test (lifecycle-compaction-reason, final review): the journal test does not remove its temporary home folder when it exits. That leak predates the lane. The folder stays inside the system temp folder.
- Desk changes endpoint (knowledge-freeze-notice CI): the event-loop check failed once on the macOS suite leg at 793b0494, worst gap 133 ms over 223 ms. The lane touched no desk code (a runner flake, inferred).
