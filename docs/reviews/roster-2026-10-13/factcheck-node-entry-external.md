| X17 | "Node's docs say a `detached` child on Windows gets its own console window … a desktop seat may see one per attempt, and closing it ends that attempt"; `windowsHide` is "a one-line follow-up" (§6.13) | Doc quote VERIFIED; the inference is CONTRADICTED by source (runtime UNVERIFIED) | libuv turns `detached` into `DETACHED_PROCESS \| CREATE_NEW_PROCESS_GROUP` (v1.x `process.c:1128`; Node 22's 1.51.0 `:1063`). Microsoft says that under `DETACHED_PROCESS` the process "does not inherit its parent's console … can call AllocConsole … later". So pi (`node.exe`) runs with **no** console window, and there is nothing to see or close. `windowsHide` adds `CREATE_NO_WINDOW` (libuv `:1099-1106`), which Microsoft says "is ignored … if it is used with either CREATE_NEW_CONSOLE or DETACHED_PROCESS". Windows PowerShell 5.1 also uses Legacy native argument passing, which does not preserve embedded `"` (7.5 `about_Parsing`, "Passing arguments that contain quote characters"; the `Windows` mode is the default only from 7.3). Claude Code treats PowerShell as the primary Windows shell (prior E9). This is the seat-to-launcher hop, which the Node-entry switch does not touch. The README needs a PowerShell form, for example `-p (Get-Content -Raw brief.md)` on 7.3+ or `@<path>`, or the claim should be scoped to Git Bash. |
