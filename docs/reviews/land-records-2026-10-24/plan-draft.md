## 2. The record

- **Where:** `<git common dir of --main>/nana/land-records.jsonl`, found once through `repoKeyOf(main)` with `git:` stripped, as build-report does. Why: every worktree shares it, cleanup keeps it, it sits beside the build ledger so build-report reads both with one lookup, a suite's fixture lands write into the fixture's own `.git`, and `repoKeyOf` already handles a second spelling (R-1355). Not `~/.pi/agent` (mixes repositories) and not the suite-runs folder (the 300 cap is the audit's complaint).
- **Two kinds, build-records form (D2/D3 precedent).** A `start` line before the first check, an `end` line when the attempt ends. A start with no end reads `no end`: interrupted, killed hard, crashed or still running. nana-land runs the suite through `spawnSync`, so a Ctrl-C kills node before any handler runs (inferred); the start line is the only honest way to see an interrupted land. No signal handler is added.
- **Start fields:** `v` 1, `kind`, `attempt` (randomUUID), `startedAt`, `pid`, `main`, `tree` (resolved paths), `lane` (the source tree's branch `feat/<lane>` under the cleanup lane-name pattern, else null), `tip` (source HEAD full id, or null), `items` (each `--reviewed` item through `canonicalItem`, the raw text cut to the slug bound when it throws).
- **End fields:** `v`, `kind`, `attempt`, `endedAt`, `durationMs`, `outcome` (`landed` | `refused`), `stage` (null, or `preflight` | `ci` | `suite` | `merge`), `reason` (null, or the refusal's first line without `refused: `, capped), `tip` (resolved, or null), `ci` (`passed` | `skipped` | `refused` | `not reached`), `ciRuns` (for each judged run: `workflow`, `id`, `attempt`, `createdAt`, `startedAt`, `updatedAt`, as GitHub gave them; empty unless CI passed), `ciWaitMs`, `suiteMs`. Stage boundaries: everything before the CI scope read is `preflight`; the scope read, gh and `judgeRuns` are `ci`; the suite result is `suite`; everything after the suite passed (second tally read, rechecks, merge, containment) is `merge`.
- **Every attempt:** landed (end after the CI-records step, so `durationMs` is the whole land); refused before the suite (`suiteMs: null`, `ci: "not reached"` or `"refused"`); refused by CI (`stage: "ci"`, `suiteMs: null`); refused by the suite (`suiteMs` set, reason `suite failed (exit N)` only, never the suite output); refused after the suite (`stage: "merge"`); interrupted (start only). Argument refusals in `parseLandArgs` and a `--main` outside any repository write nothing (no clone to write to); the second prints one `land record:` note. `nana-land cleanup` writes nothing.
- **CI wait:** `max(updatedAt − createdAt)` over the judged runs, in ms; null when CI did not pass or any time is missing, unparseable or negative. The CI verdict and its lines never depend on these fields.
- **Clock:** one injected `now` (default `() => new Date()`) for `startedAt`, `endedAt`, `durationMs` and `suiteMs`, as `keepLandCiRecords` injects its clock.
- **Atomicity and cap:** one `appendFileSync` per line, no lock (build-records D2); a torn line is skipped and counted. Both appends sit outside the review-ledger lock, so the ledger never lengthens the lock hold. No retention, so land records outlive the 300-run cap; reads are bounded at `LAND_LEDGER_READ_MAX_BYTES`, chosen 32 MiB: about 1.2 KB an attempt and about 20 attempts a day (31 suite-reaching lands in 2.3 days measured, refusals inferred) gives about 3.8 years. Every record step runs in its own guard and never changes the exit code, the merge or any other line (R-2813).

## 3. Consumers that act on it, ranked

No consumer may change a land verdict from history: a gate that refuses on past attempts would be a new, non-deterministic failure. "Acting" here means code that reads the ledger and puts the facts in front of the seat when it decides.

1. **build-report land lines (in lane).** Value: answers the audit per lane: attempts, refusals by stage, total, suite and CI wait minutes, interrupted lands. It gives the owner's open ask ("What a land waits for") measured numbers. Cost: a reader, pairing, three line renderers, about 60 lines, one test. Printed after the build lines; with no land ledger the output is byte for byte today's, so R-2600's test is the guard.
2. **nana-land's own end line (in lane).** After the end append, nana-land prints one `[nana-land] land record:` line with this attempt and its lane's land line, exactly as build-report prints it (R-2602 precedent). Value: at every attempt, refused or landed, the seat sees how many tries the lane took and the time spent; the seat's land report carries it. Cost: small, reuses the renderer. Reader of its own artifact, so no `Reads:` line.
3. **Product page age (split, FEAT-039).** Add the land ledger as a fourth `ARTIFACT_AGE_TABLE` key with a reader mapping end records to tip and `endedAt`. Value: the card shows when the last land record was written, so a broken writer shows as a stale age. Cost: R-2793's text and test (A-082 joins A-006, A-032, A-033), R-1012's input list, one reader, `Reads: A-082 · scripts/product-report.mjs, packages/nana-pack/lib/land-records.mjs` in FEAT-039. This crosses into FEAT-039, so it is a separate small ordinary lane after this one lands; it can take A-059 (ci-runs) in the same change.
4. **Previous-refusal or CI-wait-estimate notes in nana-land (later).** Naming the last refusal for the same tip, or a median of recent CI waits when CI is still running. Value: modest; the seat already sees the refusal. Defer until build-report numbers show repeat refusals are common.
5. **Session start or frontier line (no).** A hook change makes it a hook lane in another feature; the value is low until data exists.

**Recommended set for this lane: 1 and 2**, plus the deliverable claim in section 4 so the page's "Artifacts no other feature reads and no deliverable names" list does not gain the new entry.

## 8. Threat model

In scope, honest variation in our tools' output: two lands of one clone at once; a land killed mid-suite (Ctrl-C, closed terminal, SIGKILL); a suite killed by signal; `.git/nana` as a file or the ledger as a folder; torn, other-schema or orphan lines; a source tree detached or off `feat/`; a `--main` outside any repository; `--tree` and `--main` in different clones (R-1009: the record goes to main's clone); items that fail `canonicalItem`; a run object without times, or with a negative span; a re-run attempt; a ledger over its cap; Windows paths (8.3, case) and a second spelling of main (R-1355). Out: deliberate forgery, such as a hand-edited ledger or forged CI times. A finding outside this model is a residual.

Known limits (the seat writes them before the final round): argument refusals and a `--main` outside any repository are not recorded; `no end` cannot tell interrupted from running; the CI wait is recorded only when CI passed; a merge-stage refusal may follow a completed fast-forward; records are per clone and start at this lane; the page shows `age not measured: clone store` until the FEAT-039 lane; no lock, so a same-instant tear is possible (inferred never on a local disk).

## 9. The claim I would most expect to be wrong

That `updated_at − created_at` of the newest judged run is "the CI wait". A re-run inflates it with the gap before someone asked for the re-run: run 39491555085 (attempt 2) spans 57 minutes from creation to update, while attempt 2 itself ran 3.5 minutes. It measures CI's span, not the seat's idle time, and `updated_at` may move after completion (inferred). Keeping all three timestamps per run lets a later reader recompute it.
