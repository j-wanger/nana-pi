# Claude Code builder parity: proxy and login carry, measured on claude 2.1.299

Date: 2026-10-22. Machine: macOS (Darwin 25.2.0, arm64). Binary: `~/.local/share/claude/versions/2.1.299`.
Harness root: `<scratch>/ccbp-proxy/` (written `$P` below).

## Method

- `$P/run.mjs` runs one case. Each case gets a fresh temp HOME with a user rule, a user CLAUDE.md, and an optional `settings.json` or `CLAUDE_CONFIG_DIR` folder. It starts fake Messages endpoints A, B and C, plus an optional recording proxy, and runs claude with a clean env.
- Each case folder `$P/cases/<case>/` holds `cmd.json` (exact argv, env and ports), `out.txt` (claude's output), `api-<A|B|C>.log` (one JSON line per request: headers incl. `x-api-key` and `authorization`, url, tools, memory-prompt flag), `api-*.log.system.txt`, `.firstuser.txt` and `.tools.json`, `repo/echo.txt` (what the builder's Bash tool saw in its env), `summary.json`, and, where used, `proxy.log`, `helper-ran.txt`, `hook.log` and `carry-settings.json`.
- Base argv is the launcher's: `-p --model fable --permission-mode default --setting-sources project,local --strict-mcp-config --tools Read,Grep,Glob,Bash,Edit,Write --allowedTools Read,Grep,Glob,Bash,Edit,Write --append-system-prompt-file <file> "Do the task."`. Cases add `--settings <file>` or drop `--setting-sources` as named.
- Base env: `PATH`, temp `HOME`, `ANTHROPIC_BASE_URL=<A>`, `ANTHROPIC_API_KEY=sk-ant-fake-key`, `NANA_ROLE=worker`, `NANA_WORKTREE_ROOT`, `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`, both `BASH_*_TIMEOUT_MS=3600000`, `DISABLE_TELEMETRY=1`, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`.
- Safety additions, not part of the launcher's env: `CLAUDE_SECURESTORAGE_CONFIG_DIR=<temp HOME>/.claude`. The code shows it gives the keychain item a hashed service name, so no real credential can be read (`$P/evidence/code-excerpts.txt`, OU()). The fake endpoint logs any key that is not one of the probe's own fake keys as length and prefix only. No real model ran. Every base URL was a local fake, and the proxy refused every host it did not map.
- The fake endpoint scripts one Bash tool call: `printf ... > echo.txt`. That records which value of each probe name the builder's tools actually received.
- Code reading used `$P/ctx.mjs` over the binary. Key excerpts are in `$P/evidence/code-excerpts.txt`, full strings in `$P/evidence/strings.txt`.

## What this means for the carry design

1. **Carry is needed only for the user settings file.** A proxy in the Windows system or user environment, or in the shell profile the launcher starts from, is already in the launcher's `process.env`. It reaches the builder with no carry (measured with a process-env proxy on macOS; Windows env inheritance inferred). A proxy, CA path or helper in the user `settings.json` is dropped today by `--setting-sources project,local` (measured). That is the case the carry fixes.
2. **Managed settings need nothing from the launcher.** Policy settings load whatever `--setting-sources` says (code; measured for permissions through the flag). Corporate managed `env`, proxies and login policy reach the builder on their own. The launcher must not copy them. Residual: file, MDM and registry managed `env` were not measured here (needs root or Windows).
3. **Read the right user file.** Use `$CLAUDE_CONFIG_DIR/settings.json` when that variable is set, else `<homedir>/.claude/settings.json` (measured on macOS; the Windows homedir path is inferred).
4. **Sealed values must be written into the carry file, not only into the process env.** A `--settings` env beats the process env (measured for base URL, a probe name, and auto-memory, where `=0` re-enabled memory). The launcher should drop its sealed names from the carried `env` and then write its own sealed values (`NANA_ROLE`, `NANA_WORKTREE_ROOT`, `CLAUDE_CODE_DISABLE_AUTO_MEMORY`, `BASH_DEFAULT_TIMEOUT_MS`, `BASH_MAX_TIMEOUT_MS`) into that same `env`, last. A managed policy `env` would still beat both (inferred from the source order); that is company policy and stays a residual.
5. **Copy keys by allowlist, never the whole file.** A `--settings` file runs its hooks and applies its permissions (measured). Top-level keys worth carrying: `env` (filtered), `apiKeyHelper` (measured to work), `proxyAuthHelper` (works only with `CLAUDE_CODE_ENABLE_PROXY_AUTH_HELPER=1` in env), `awsAuthRefresh`, `awsCredentialExport`, `gcpAuthRefresh` (schema keys, not measured). Do not carry `forceLogin*`: flag settings ignore them (inferred). Do not carry `hooks`, `permissions`, `plugins`, `processWrapper` or MCP keys.
6. **Filter `env` by name.** Carry proxy names (`HTTPS_PROXY`, `HTTP_PROXY`, `NO_PROXY`, lowercase forms), CA and client-cert names (`NODE_EXTRA_CA_CERTS`, `CLAUDE_CODE_CLIENT_CERT`/`_KEY`/`_KEY_PASSPHRASE`, `CLAUDE_CODE_CERT_STORE`), the endpoint and auth names (`ANTHROPIC_BASE_URL`, `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_CUSTOM_HEADERS`), the provider switches and their cloud credentials (`CLAUDE_CODE_USE_BEDROCK`/`_VERTEX`, `AWS_*`, Vertex names), and `CLAUDE_CODE_ENABLE_PROXY_AUTH_HELPER`. Never carry `CLAUDE_CONFIG_DIR` or `CLAUDE_SECURESTORAGE_CONFIG_DIR`: they move the config home and the keychain item (the binary says a settings-env `CLAUDE_CONFIG_DIR` is honoured; inferred). The exact name list is a design choice, not a measurement.
7. **Side effects to state in the contract.** Carried `env` also reaches the builder's Bash commands (measured: the carried `HTTPS_PROXY` was visible in Bash). That matches a normal session: git and npm use the proxy. Claude does not bypass loopback by default (measured), so a carried proxy without `NO_PROXY=127.0.0.1,localhost` sends local calls to the proxy too. With an env API key and a carried `apiKeyHelper` both present, two different credentials go out (measured). The launcher should not add or remove keys of its own.
8. **The carry file can hold secrets.** Write it outside the worktree, user-only (0600), and delete it after the run. This is a recommendation, not a measurement.
9. **Not measured here:** OAuth (subscription) login on a machine behind a proxy. The launcher sets no `CLAUDE_CONFIG_DIR`, so the builder reads the same keychain or credential-store item as a normal session (inferred from the code). These probes blocked the real keychain on purpose.
