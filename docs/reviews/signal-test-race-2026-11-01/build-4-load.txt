# Build 4 CPU-load probe

- Cause: a missed R-2693 delivery retried without stopping its worker. In the small-builder case, `WC_HOLD_FILE` named a file nobody creates, so fake pi waited until the 10-second wall-clock ceiling. CI run 41367446804 killed the test file after 21.2 seconds, during R-2693; the earlier macOS run failed an assertion instead. Each miss now sends SIGTERM immediately, and the unused hold-file setup is gone.
- Suspect (a) ruled out: startupSignalCase signals only the pi-worker child. For cleanup, the small pi fixture is detached and its pid is its group id; the larger fake Claude fixture is not detached, so the negative-pid group lookup misses and fallback kills only its pid. Neither targets the test process.
- Before fix: worker-claude test under four `yes > /dev/null` CPU loaders — 10 passed, 0 failed.
- After fix: worker-claude test under four `yes > /dev/null` CPU loaders — 10 passed, 0 failed.
