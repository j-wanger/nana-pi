# land-test-split — plan attack

## Verdict

The cut works in principle. The adversary read every check at ac20e30a. No check reads another check's leftovers through module state, a reused temp name (`tmpDir` is `mkdtempSync`, tmp-dir.mjs:20-24), cwd or `process.exitCode`. nana-land and its libs hold no mutable module state. A1's conclusion holds, but its stated basis misses process state (finding 6). Four problems would still give a wrong or unprovable lane: the check counts, the `runLand` name clash, the new rows' `// req:` tags against M3, and M3's undefined block for the win32 SKIP. Lane class with the real new names (`land-ci-read`, `land-merge`) is `ordinary`. `test-runner-config.mjs` alone prints `gate`, so leaving it untouched is correct.

## Findings

1. **MUST: the check counts are wrong, so M4's sum cannot hold.** `grep -c '^check(' land.test.mjs` is 66, and the runtime-map check (land.test.mjs:696) is one of them. On win32 that gives 65 PASS + 1 SKIP. The timings agree: 65 PASS lines + 1 SKIP (timings-before-win32.txt:3-68). The last block (692-908) holds 17 checks on win32 plus the SKIP, and 18 on POSIX. The plan says 15 and 16, so the table sums to 63, not 65. Purpose says "66 of 66" and M4 says "66 PASS and 1 SKIP". The precedent's own suite log says "65 PASS" (windows-local-suite-2026-11-01/suite-run-win32-powershell.txt:4). Fix: table row 4 becomes "17 on win32 (+1 SKIP), 18 on POSIX". M4 becomes "65 PASS and 1 SKIP on win32, 66 PASS on POSIX".

2. **MUST: moving `runLand` into `land-fixtures.mjs` cannot keep its body byte-identical as O2 and M3 require.** `land-fixtures.mjs:15` already imports nana-land's `runLand`, and `executeCi` calls it (land-fixtures.mjs:98). The test-local `runLand` (land.test.mjs:44-54) is a wrapper that calls `executeLand`, the alias at land.test.mjs:19. Exporting a second `runLand` from the fixture is a duplicate-binding SyntaxError. Renaming the import to `executeLand` changes `executeCi`'s body, or silently rebinds it to the wrapper. Under O1, `runLand` is used by land.test.mjs and land-merge.test.mjs (for example :461, :720, :861), so the move is forced. Fix: the plan names the move. The fixture imports `{ runLand as executeLand }`, and `executeCi` keeps calling nana-land directly. M3 then allows exactly that one import-line and call-site change in `land-fixtures.mjs`, and requires every other existing fixture export to stay byte-identical. Alternatively, export the wrapper under a new name and make M3 allow that rename at call sites. Either way, say which one.

3. **MUST: the new rows need `// req:` tags, and M3 forbids them.** An `implemented` row with no `// req: <id>` marker fails the trace rail (templates/typescript/template/tests/requirements-trace.ts:520-522). The precedent tagged existing checks by editing their req lines, for example `// req: R-3230 R-3454` (profile-store.test.mjs:22) and `// req: R-714 R-3455` (review-ledger.test.mjs:48). M3 makes "its `// req:` lines" part of a byte-identical block, and M5 needs `requirements-trace.mjs` green. Both cannot hold. The plan also never says which check carries each R-3490 to R-3494 tag. Fix: name the tagged check for each row. M3 compares req lines after removing exactly the added `R-349x` tokens, and it lists each such addition.

4. **MUST: M3's block definition does not cover the win32 SKIP block, and its end is ambiguous.** The runtime-map check sits inside `if (process.platform === "win32") console.log("SKIP …"); else { // req: R-2531  check(…); }` (land.test.mjs:693-717). Its req line is inside the `else`, and the SKIP line is printed outside `check()`. Read literally, M3 compares the inner `check(` only, and a move that drops or alters the guard or the SKIP text passes. "Through the closing `});`" is also loose, because many checks hold inner `} });` lines (for example :88, :505). Fix: define a block as the first `// req:` line through the first line that is exactly `});`. Define the R-2531 block as lines 693-717 whole. Extend M3 to two more things: each helper copied locally (`tallyRows`, `writeTallyRows`, `recordTextReview`, `assertCiRefused`, `check`), and the `TEST_LOCKED` and `PI_REVIEW` constants (:27, :29), which must move unchanged with the checks that read them (:707, :903).

5. **SHOULD: A2's basis is upside down, and the cut leaves the CI file nearest the budget.**
   - A pool timeout at 300 s gives only a lower bound on the pool ratio, not the upper bound 1.3. The usable data point is the precedent run: 54 pass + 1 fail + 1 skip in 300 s, against 283.7 s alone (suite-run-win32-powershell.txt:4, :108). That gives about 1.15 from one sample. The alone time itself ranges 214 to 297 s, about 1.4×, and CI shows two bands about 1.45× apart (FEAT-031.md:109).
   - The runner collects files sorted (scripts/test.mjs:177, :190) and pulls them in that order (:563-571). `land-ci-read`, `land-ci-records`, `land-ci-suite` and `land-merge` therefore start together in the four-slot pool, all git-heavy. That is denser load than any measured run.
   - The 119 s CI file × 1.4 alone spread × 1.15 load ≈ 190 s, above M1's 180 s.
   - Fix: rebalance so no file exceeds about 100 s alone. For example, R-2589 and R-2590 (68 s) go in one file, and the other six CI checks (51 s) join the kept-text block. Or make it four files. Restate A2 from the 1.15 sample. Name the clustering as a residual, or choose names that do not sort together.

6. **SHOULD: A1 omits process-level state, and the baseline ran outside the runner.**
   - Three checks call nana-land without `home`: :264, :274 and :875. They fall back to `os.homedir()` (nana-land.mjs:84).
   - R-2591 mutates `process.env` and restores it in `finally` (:650-665). The in-flight checks admit under `process.pid` (:283, :294, :305).
   - None of these leaks between checks, and the adversary verified that. A1 should still say so, because the runner gives every file a fresh HOME and TMP (scripts/test.mjs:475-480), and the split changes which checks share them.
   - The timings were taken with `node land.test.mjs` (timings-before-win32.txt:2). That run read the real user HOME and ledger, and could take the real ledger's lock via :274.
   - Fix: M4's alone runs, and any re-baseline, go through `node scripts/test.mjs <file>`, so HOME, TMP and env match the suite. Add these three items to A1 as checked.

7. **SHOULD: move the code-map exemption, do not copy it.** The only site needing it is :600, `execFileSync(locate[0], …)` in R-2589 (docs/code-map.md:3660, "repo-code launches — line 600"). That site goes to `land-ci-read.test.mjs`. `map:check` flags only a missing entry (scripts/code-map.mjs:64), not a stale one, so a leftover `land.test.mjs` entry at code-map.config.json:67 would pass unseen. Fix: M5 requires the entry on exactly the file holding that line, and the entry removed from `land.test.mjs` if that file no longer needs it. Update `land-fixtures.mjs`'s `@purpose` and `@outputs` if it gains the wrapper.

8. **SHOULD: three of the five rows have no lasting test.** M3 (byte-identical moves), M4 (alone runs) and M5 (trace, map and config unchanged) describe this lane's process, not behaviour a check pins. Tagging them on an unrelated land check makes the trace claim a test that does not test them. Fix: follow R-3454 and R-3455 (REQUIREMENTS.md:3002-3003). Use one or two rows: "each file ≤ 180 s in a full run" and "every original check name runs exactly once". Keep M3 to M5 as lane-folder evidence without rows, or record why each needs a row.

   - The SKIP name is the text between `SKIP ` and ` — R-2526` (:693). R-2589 can print its own `SKIP R-2589 child …` line on a machine where gh sits beside git (:611-612). Both lists must treat that line the same way.
