- **F7 (MUST, land review r2) — the kill step loses a child whose parent has exited.** Since build 5, `signalChild` in `scripts/test-locked.mjs` walks the tree again from the child for each signal (`killTree` in `scripts/runtime-measure.mjs`). Suppose a descendant handles or ignores the first signal, or takes longer than 500 ms to stop, while its parent exits at once. That descendant is no longer below the child, so the SIGKILL step 500 ms later misses it. The locked suite then releases its lock and exits with suite processes still running. On main the kill step signalled the child's process group (`kill(-pid, SIGKILL)`), which reached a same-group orphan. Both reviewers reproduced it with SIGINT, SIGTERM and SIGHUP on the production hand-measure command; earlier data and coverage cleanup stayed correct. Fix: the first signal remembers every target it signalled (the process groups and the single PIDs from the tree walk), and the SIGKILL step signals those again, plus the child's own process group as on main, plus a fresh walk from the child. Keep `killTree`'s rule that a group holding a process outside the tree (the caller's own group) is never signalled as a group. A PID that has gone (ESRCH) is not an error.
- **N3 (final review r2) — on Windows a Ctrl-C to the hand measure now force-kills the locked suite.** On win32, `child.kill(signal)` in `handMeasure()` is TerminateProcess, so the locked suite can die before it removes its coverage folder or releases the lock. Before build 5 the measure command simply died, and the locked suite ran its own handler on the console's Ctrl-C. On Windows, do not forward the signal: the console delivers Ctrl-C to the locked suite itself; keep waiting for it and return non-zero after a stop. R-1277 stays off Windows.
