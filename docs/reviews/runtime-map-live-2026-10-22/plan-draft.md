# Lane plan draft: runtime-map-live (main 08c33d94)

Probe: `git archive` copy of main, `git init`, temp HOME, the real machine lock. One full run (the measure command), plus filtered single-file runs.

## 1. What the lane changes

Every land's locked suite runs under per-file coverage and writes the runtime map for the tip it lands, so main's map matches main's tip after each land. nana-land passes the tip to its suite; nana-pi's locked suite does the measuring, inside the machine lock. A map problem never changes the land's verdict: a coverage run that fails is followed by a plain run whose exit code decides. The impact command prints the measured tip, its time and age, how many tracked files differ, and what to run when main has moved past it.

## 3. Decisions

- **D1 Scope.** (a) Land measures and impact shows freshness, both FEAT-029. (b) Add per-run records. (c) All four, CI included. Recommend (a). Records and CI artifacts change the runner's R-1270 contract and need their own reader, so they form the next lane, "suite-records", under FEAT-031, with the land ledger line under FEAT-008. Default: `narrow`.
- **D2 How a land measures.** (i) nana-land sets `NANA_LAND_TIP` in its suite's environment; the locked suite measures when it names HEAD. (ii) The seat passes `--suite "npm run map:measure"`: an ordinary lane, but a rule makes the map. (iii) Every clean unfiltered locked run measures: coverage on every builder run, and lane tips overwrite main's map. Recommend (i): no rule, and nana-land stays generic. Default: `env`.
- **D3 Where data lives.** One file, overwritten per land, at the git common dir's `nana/runtime-map.json`, as today. It gains `tip` (full SHA) and `measuredAt` (UTC ISO); schema stays 1, so older readers in other worktrees ignore the fields and R-1276 holds. No history in this lane. Per-tip copies or a history fail the subtraction test while lands measure. Default: `overwrite`.
- **D4 Merging per-run seconds.** None in this lane: each land's coverage run gives both the ran sets and the seconds (parallel seconds under load, as today). The records lane may add serial CI seconds per platform as a separate field, never replacing ran sets. Default: `none`.
- **D5 Land when measuring fails.** Coverage run passes: exit 0, data written; a write failure prints one line and still exits 0. Coverage run fails: one plain run, whose code decides; data unchanged; a line names the files that failed under coverage. Windows, a filtered run, or a tip that is not HEAD: plain run only, one line. Stopped: as today, plus the coverage folder removed. Options: `rerun` (this), `double` (plain and coverage every land, about 6 more minutes each), `trust` (coverage verdict; fix tests at source). Trade: rerun gives a file that fails under coverage one plain second chance, so a flaky failure can pass the land, printed. The seat's call, or the owner's if it reads as a change to the land rule. Default: `rerun`.
- **D6 CI artifacts.** Deferred to suite-records. Shape for that lane: each leg uploads `suite-timings-<os>` with `if: always()`, one JSON {sha, platform, exit, files: {path: {label, seconds}}} of about 17 KB, `retention-days: 14` (chosen: covers the weekly priority review; GitHub's default is 90). A merge command reads a run's three artifacts. Default: `defer`.
- **D7 Freshness in impact.** One line: `runtime map: measured at <tip8> <UTC time> (<h> h ago); <n> of <m> tracked files differ from this checkout`. When main is not the tip, one more: `main is <k> commits past the measured tip` or `the measured tip is not on main`, then `the next land measures it, or run npm run map:measure in a clean main checkout`. R-1274's whole-section stale marks stay. Options: line (this), per-file stale marks (a recorded limit; finer, more code), refuse output. Default: `line`.

## 5. Class, tunables, limits, threat, files

**Class.** An install, hook or gate lane: it changes nana-land. Roster reviewer, land reviewer, the seat's wrong-code pairs (one per row: drop the variable; return the coverage code without a rerun; rerun under coverage; let a write error exit 1; measure on Windows; skip the folder removal; omit the count; count commits the wrong way), one independent check, the Windows CI leg. The install-check runs on macOS before nana-land, because install.test.mjs sits under packages/nana-setup/. A larger lane: the roster's largerBuilder through `pi-worker --lane-size larger`. It shares the roster reviewer's lineage, so the seat names a reviewer from another lineage. Feature: FEAT-029 · Navigate code and investigate impact. Carry `requirements-moved.mjs` output in both briefs.

**Tunables** (new `packages/nana-pack/lib/land-config.mjs`; runtime-map-config.mjs for the rest):
- `LAND_TIP_ENV` "NANA_LAND_TIP": contract (R-2522, R-2523); chosen NANA_ prefix, so R-618's scrub keeps it out of every test file.
- `UNMEASURED_PLATFORMS` ["win32"]: contract (R-2526); reason: FEAT-029's Windows path and stop bugs.
- `MAIN_REF` "refs/heads/main": contract (R-2529; lands go to main).
- `TIP_DIGITS` 8: chosen (this repo's records cite 8). Age in whole hours: chosen.
- Data fields `tip`, `measuredAt`; schema 1 kept: contract (R-2523, R-2528); chosen additive.

**Known limits.** A land refused after its suite passed leaves the map at an unlanded tip; R-2529 says so until the next land. Seconds stay parallel seconds under load (FEAT-031). The rerun can pass a flaky file; a coverage-only pass, a file failing plainly but passing covered, passes too (inferred rare). Windows lands never measure; Linux lands are untested by hand. Old data without a tip prints no freshness line. Any edit still marks the whole section stale; the count shows how many files. The measure command's own write stays outside the lock (FEAT-029's two-at-once bug). A land needs about 1 GB of temp space; a full disk fails the coverage run, and the plain run decides. Only the locked suite measures: `--suite "npm test"` does not. CI never measures.

**Threat model.** Honest variation is in scope: a land stopped mid-measure (R-2527), a filtered run, Windows (R-2526), two worktrees running suites (the machine lock; the land writes inside it), a test that behaves differently under coverage (R-2524), a land refused after its suite. A failing CI leg is untouched: this lane does not change CI. Deliberate forgery is out: a hand-set `NANA_LAND_TIP`, a hand-edited data file.

**Files.** `packages/nana-pack/bin/nana-land.mjs`, new `lib/land-config.mjs`; `scripts/test-locked.mjs`; `scripts/runtime-measure.mjs` (run and write split, so the locked suite reuses the write); `lib/runtime-map.mjs`, `lib/runtime-map-config.mjs`, `scripts/code-map.mjs`; `packages/nana-setup/tests/install.test.mjs`; tests `land.test.mjs`, new `runtime-land.test.mjs`, `runtime-map.test.mjs`; REQUIREMENTS.md; README.md's map paragraph; the pack README's land section (the suite's new variable); known-bug lines in FEAT-029 and FEAT-031; HANDOFF; regenerated map and tree.
