# windows-local-suite — plan attack

## Verdict

The three root causes hold: CRLF splitting and backslash forbidden paths in the restore test, the duplicate `Path`/`PATH` key reaching `envValue`, and two files over the 300 s default. The plan around them has five problems. It is not an ordinary lane once `test-runner-config.mjs` is edited; `scripts/lane-class.mjs` returns `gate` for that file. It misses that a runner-wide timeout override exists and that CI already runs at 900 s, so the Windows CI leg was never held to the 300 s limit. The O1 default for profile-store cannot satisfy A4 and M5 together. The M5 budget is measured alone, but the file runs in the four-file pool, so the budget does not prove the claim it makes. The review-ledger split carries an unnamed shared state, repo A's HEAD and an untracked file, and the name-multiset pin cannot see it. Several must-meets also have pins that are wrong or can pass vacuously: M1's check count, M2's predicate, the scope of M3's row, and M5/M6 being measured on Windows only. Fix the findings below before building.

## Findings

1. **MUST: the lane class is `gate`, not `ordinary`.** `node scripts/lane-class.mjs --root . --files packages/nana-pack/lib/test-runner-config.mjs,...` prints `gate: packages/nana-pack/lib/test-runner-config.mjs — CI verdict nana-land reads`. M6 requires editing `RUN_ALONE` in that file (test-runner-config.mjs:60-69), so the header's `ordinary` came from a file list without it. The owner's words also say "ordinary". Change: keep the lane ordinary by leaving `RUN_ALONE` alone. `review-ledger.test.mjs` stays the run-alone file and keeps the load-sensitive blocks: §5 races (review-ledger.test.mjs:757), §6 crashed reservation (:777), §8 expired reservation (:833), §18 renewal (:1349) and §19 TOCTOU (:1385). The other blocks move to new pool files. Then drop the RUN_ALONE half of M6 and the `test-runner-config.mjs` forecast. If the builder must touch the config, the plan has to say gate and carry the gate-lane duties, and the owner has to be asked first.

2. **MUST: the timeout premise is wrong.** The plan says "no per-file override exists" and, under Residuals, "The runner has no per-file limit override". But `scripts/test.mjs:89` reads `NANA_TEST_TIMEOUT_MS` for every file (R-612), and CI sets it to 900000 (`.github/workflows/ci.yml:77`, R-2558, "about twice review-ledger's projected 412 s at four on Windows"). So the Windows CI leg is not failing on time. Only a local run at the default fails. Change: rewrite Purpose item 3, A2 and Residuals to say this. State why splitting beats running the locked suite locally with `NANA_TEST_TIMEOUT_MS=900000`, for example that a land on a laptop uses the default and that `docs/known-bugs/FEAT-031.md:49` records lands failing on time-outs alone. Or adopt the env route and drop M5/M6.

3. **MUST: O1's profile-store default contradicts A4 and M5.** The 39-save daily-cap loop (profile-store.test.mjs:44-45) sits inside check 1, "a save writes one shape record…" (:23-48), next to the shape, refusal and guide assertions. Putting "the daily-cap loop alone" in a part means splitting that check into two named checks. That breaks "each original check name appears exactly once" (A4, M5) and R-3230's evidence cell (REQUIREMENTS.md:513). Leaving check 1 whole leaves one part at about 165 s of the 180 s budget, about 8% margin, from one check that no file split can shorten. Change: either keep check 1 whole and reduce its cost (see finding 12), or allow the rename explicitly and update R-3230's evidence.

4. **MUST: M5's 180 s alone budget does not prove "fits the 300 s limit under four-file load".** profile-store is not on `RUN_ALONE`, so it runs in the pool (scripts/test.mjs:516-518), next to the git-heavy `memory-run*` siblings that use the same fixture. A part that takes 165 s alone has no measured time under load. Change: add to M5, and to M6 for any part in the pool, a pin from one full `npm run test:locked` run on the reference laptop. Each part's reported seconds in the suite record must be ≤ 240 s, which is 80% of 300 s, and the run's file table goes in the lane folder. The alone budgets stay as a secondary check.

5. **MUST: A3 is false. Blocks inherit repo A's state without naming it.** `A` and `B` are built once at module level (review-ledger.test.mjs:109). The `redirect` block (:686-709) writes the untracked `A/redirect.log` and never removes it, so every later block that uses A runs on a dirty tree, and the revision becomes HEAD plus a snapshot. These blocks use A without first calling `A.at()`: `0` (:127), `unread-rounds-left` (:398), `redirect` (:686), `shape` (:712), `13`/`14`/`15` (:1030, :1067, :1088), `17` (:1328), `20` (:1418) and `21` (:1551). They run on whatever HEAD and debris the previous block left. Moved into a fresh file, they start on a clean, branch-attached A at `shas[5]`. A check can still PASS there while it exercises a different revision form, and the M6 name multiset cannot tell. Change: A3 must name repo A's HEAD and working-tree state as shared state. The plan names the cut. The fixture or each moved block re-creates the inherited A state explicitly. The builder records A's `git rev-parse HEAD` and `git status --porcelain` at entry to each moved block, before and after the split, and shows they are equal.

6. **MUST: M5 and M6 compare name lists recorded on Windows only.** The §7 signal block (review-ledger.test.mjs:806-831) runs only off win32, and its names are generated (`signal-${launcher}-${sig}`). The Windows timings show a single SKIP line for it. A split that drops §7, or that breaks the `10-ro` gating, keeps the Windows multisets equal. Change: record the before and after check-name lists from a POSIX run too. A CI macOS or Linux log of main against the branch is enough. Require equal multisets on each platform.

7. **MUST: M1's pin says "passes with 15 checks".** The file has 15 `check(` calls today (`grep -c '^check('`). M1 and M2 each add one, so the count after the change is 17, unless those two checks live in another file, which the plan does not say. Change: write "17 checks, 0 failed", or name the file the two new checks live in.

8. **MUST: M2 can pass vacuously.** (a) "A synthetic listing … built from the same forbidden list" is circular. If the listing comes from `forbiddenArchivePaths` and both sides go through the same normalization, the check passes whether or not the slash normalization exists. (b) Nothing pins that the real check (restore.test.mjs:152) calls the tested predicate. A copy in the unit check would pass while line 152 keeps the backslash bug. (c) On POSIX, `path.relative` already yields `/`, so the mutation "remove normalization" only fails on win32. Change: the synthetic listing is the literal string `.pi/agent/auth.json\r\n`. Line 152 and the new check call one named function. The mutated run on win32 is recorded in the lane folder.

9. **MUST: M3's row is false on landing.** "WHEN a test prepends a folder to PATH in an environment object, it shall do so through one helper." About 25 test files do this without the helper and stay unchanged, for example `brief-check.test.mjs:69`, `review-ledger.test.mjs:65`, `worker-lane.test.mjs:86`, `land.test.mjs:902`, `review-launch.test.mjs:180`, and `win32-launch.test.mjs:298` (`voltaEnv`) in a file this lane edits. Change: scope the row to environment objects handed to an in-process lookup (`findPi`, `findOnPath`, `piLaunch`, `stepPiRegister`, `diagnose`), which is what M4 already says.

10. **MUST: a Precedent entry breaks the planner rule.** The entry "`npm run map:search` results taken: …" does not start with a tracked path (planner.md:32). Change: split it into entries that start with `scripts/test.mjs`, `packages/nana-pack/lib/test-runner-config.mjs` and so on, each noting it came from map:search.

11. **SHOULD: correct M4's trigger and make A1 concrete.** The failure needs only the `Path` spelling. `envValue` (win-command.mjs:14-17) returns the stale original value, so the fixture is never found, whether or not a real pi is installed: see pi-registration.test.mjs:380-385 (R-1033 FAIL, then SKIP) and win32-launch.test.mjs:197-201. CI also has an npm pi on PATH (`npm i -g` at ci.yml:91), so the npm pi does not explain why CI passes. The spelling does: CI's steps run under `shell: bash` (ci.yml:71), and Git Bash hands Node `PATH`. Change: M4's WHERE clause becomes "the variable is spelled `Path`". Add a local run without a real pi on PATH, and cite ci.yml:71 in A1.

12. **SHOULD: consider a cheaper profile-store fix before splitting.** Most of check 1's 168 s is 39 CLI saves (profile-store.test.mjs:44). The cap is read from a counter file in the git folder (profile-guards.mjs:38-42), and the check counts record files (`files()`, profile-fixture.mjs:52-54). Seeding 38 records in one commit, plus a counter at 38, then making one real save and the refused one, keeps every assertion and saves about 2 minutes. That may make the profile-store split unnecessary. The git-stub idea does not work: the stub (profile-fixture.mjs:31-33) exists because `git remote get-url` expands `insteadOf`, and `pushInsteadOf` would send fetches to github.com. Change: record both options under Open choices with the measured share of the loop.

13. **SHOULD: the M3 helper should write the key as `PATH`, and the pin should say so.** `withFixtureEnv` (pi-launch-limits.test.mjs:247-249) reads `fixture.env["PATH"]` and assigns it to `process.env`, and win32-launch.test.mjs:298 reads `env.PATH`. A helper that keeps the found spelling, which is the product's own pattern at install-check.mjs:333-336, satisfies M3 as written. It then sets `process.env.PATH` to the string `"undefined"` on Windows. Change: M3 pins `Object.keys(result).filter(k => /^path$/i.test(k))` equal to `["PATH"]`. Also decide whether case-folding applies off win32, where `Path` is a distinct variable.
