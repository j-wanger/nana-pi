Feature: FEAT-039 · See the product and its decisions in one report

Class: ordinary (a generated page, the report-only deliverable module, tests, the ledger, the requirements skill's text, the README; no install, hook, gate or land-tool file). Ladder: the seat's wrong-code pairs first, then one final reviewer from another model family, and the Windows CI leg on a draft PR. Threat model: honest variation in scope — a ledger with no maker or reader line, a listed deliverable with none, a line in another capability's span, a path not tracked or staged only, a folder artifact, a merge, a sweep, a rename or a revert, an old-dated lane merged after a change, timezone offsets, a rebase that dates a change after HEAD, a shallow clone, a ledger in a subfolder, CRLF or a lone CR, no runtime data, older data with no tip or time, a tip on an unmerged branch or outside history, a dirty hand measure, `log.showSignature` set, a history whose walk passes 1 MiB, and git failures; deliberate forgery out (a forged commit date, a rewritten tip, a line naming code that never makes or reads the artifact).

Ruling: the owner, 2026-10-22, top priority — a produced artifact is a feature to maintain; the product report shows each deliverable's age and real reader instead of the derived consumers. Inputs: the planner's draft (`plan-draft.md`) and the adversary's attack (`plan-attack.md`) at main 09e38e7d.

## What changes for the owner

On the report's Product view, each deliverable stops listing the features that share its row (2 of 38 had one) and shows its own `Made by:` and `Read by:` claims as the ledger writes them. A deliverable no code makes is marked "not made by code"; one no code or prompt reads is marked "not read by code" — the same test the tree checker counts. The view opens with the checker's own count line and notes. Where a maker names an artifact, the item shows its age: the runtime map from its own record (tip, time, uncommitted files), any other file from the last commit that changed it, with that commit's short hash and subject, so a sweep reads as a sweep. Six maker lines gain the artifact they make, so seven deliverables show an age; the other 31 say "no artifact named" (S7: the trade, recorded in the land report).

## Seat decisions (not the owner's call; each is reversible)

- **D1 · Claims replace consumers; R-2452 narrowed in place.** The written claims, in ledger order, from the listing capability's own span only (M3). Consumers stay on the Features view as "Shared in" and "Shared by". R-2452 drops its consumer clause; its title changes to `R-2452: a product card lists its deliverables in line order with status and home, and marks every one not implemented as a gap`. The skill drops its derived-consumers sentence. The skill's amendment 2, which the owner adopted on 10-21 ("its consumer and check stay visible"), is not edited: the `Read by:` line is that consumer (S5).
- **D2 · Age: the maker's own record first, then git.** Only the runtime map records its own make today. Every other artifact ages by the last commit that changed it. Commits are counted as `git rev-list --count <change>..HEAD` counts them (M2: never by position in the date-ordered walk). Days are the whole-day difference of committer epoch times, clamped at 0; never calendar dates or the clock (R-1012).
- **D3 · Six artifacts named.** ` · <artifact>` on R-291 (`docs/requirements-tree.md`), R-509 (`apps/bench/studies/tool-profiles-2026-09-08/schedule.json`), R-507 (its `results.jsonl`), R-535 (its `summary.md`), R-536 (`apps/bench/studies/catch-ledger-2026-09-28/rows.jsonl`) and R-694 (`docs/reviews/writing-trial-2026-10-04/after.md`). R-694's reason becomes "the seat runs the writing-trial extractor by hand and writes its result into after.md" (M5). The skill's grammar sentence gains `[ · <artifact>]` after `manual: <reason>`.
- **D4 · One shared function for the checker's lines (M3).** `scripts/deliverables.mjs` exports one function that reads the HEAD tree through an injected runner (with the buffer) and returns the checker's exact lines: the count line under the checker's own gate, every note, and the "paths not checked" note. The tree checker prints that array; the report shows the same array. The marks use the count's own predicate, exported once. The function takes the parse the checker uses, so a lone CR gives the same line numbers (N10).
- **D5 · The walk.** One `git log` walk, run only when a maker names an artifact, with `-z -c --name-only --relative --root --no-renames --no-show-signature` and parents, through the report's git helper. Commit counts come from the parent graph, equal to `rev-list --count`. A folder artifact ages by its newest file (S1).
- **D6 · The buffer (M4).** The report's one git helper sets `maxBuffer` to the movement report's `MAX_GIT_BUFFER` (64 MiB), imported, and the walk and the ledger reads go through it. Not an urgent fix: nothing fails on main today and the failure is loud (attack N1). If the ledger passes 1,000,000 bytes before this lane lands and an assessment refresh is due, the helper's buffer ships alone first.
- **D7 · Failure degrades.** No new git call refuses the report. A failed walk or shallow check gives "age unknown" with its reason; the refusals R-1013 pins stay.
- **D8 · The runtime record.** Tip (first 8 characters), the time as UTC ISO (as R-2528 prints it), and "with N uncommitted files" when its dirty count is above 0 (S4). A tip not reachable from HEAD — a real commit on an unmerged branch included (M1) — says so; a shallow clone says "shallow clone".
- **D9 · Two builds.** (1) The shared function and the checker's use of it (output byte for byte), R-2542, R-2543, R-2452's narrowing, the six artifacts and R-694's reason. (2) The walk, the buffer, R-2544, R-2545, the skill and README text, map and outline.

## Known limits (carried to the feature files)

- 31 of 38 deliverables show "no artifact named": printed output, machine-local stores, another project's files, a release tag, main. Suite records carry their own time but name no artifact here (S6). A release tag carries a date too (N11).
- Per-lane records name no artifact; a review folder would read as fresh after every lane.
- Git ignores the report page, so the report's own age does not show.
- The last change can be a sweep, a merge, a rename or a revert; the subject shows which, and the report does not guess the last real make.
- A line names one study's files; a newer study in a new folder does not refresh it until someone edits the line.
- The runtime map's age is this clone's data, compared with HEAD here and with main in impact (N8); another worktree's land moves it; a Windows land does not measure.
- R-1012's condition does not name history depth, so `git fetch --unshallow` between two runs changes the page (N3).
- The report's existing date call takes a signature line under `log.showSignature` (N4).
- A G row in `Deliverables:` can never carry maker or reader lines (N9, FEAT-028).
- Walk time grows with history (about 160 to 220 ms at 2,514 commits on macOS); every report build in the test file adds about three spawns (N7).
- Subjects and claims with backticks or `**` render as code or bold (N6).
- The check proves a path exists, not that the code makes or reads the artifact (lane A's limit).
