## MUST

**M1. A runtime tip on an unmerged branch reads as "N commits before HEAD" (R-2545).** The runtime data lives in the git common dir, so a hand measure in a lane worktree writes a lane tip that main's report then reads. That tip is a real object, not garbage. Measured in a fixture: for a side-branch tip, `git rev-list --count <tip>..HEAD` prints 3 and exits 0; `merge-base --is-ancestor` exits 1. Only a made-up hash fails (exit 128). So a build that counts with `rev-list` passes a "tip not in history" case built from a fake hash and prints a wrong count for the real case. Fix: the R-2545 test's outside-history tip is a real commit on an unmerged branch of the fixture. Add three cases: a `measuredAt` that does not parse (a NaN build prints "NaN days"), a tip with no time, and a shallow clone. In a shallow clone, say "shallow clone", not "not in HEAD's history", which would be false.

**M2. Counting by walk position passes every planned case (R-2544, R-2545).** The walk is in date order, so a commit's position in it is not `rev-list --count`. Measured: main changes the artifact on day 5; a lane with commits dated days 2 and 3 merges on day 6. Position gives 1 commit; `rev-list --count <change>..HEAD` gives 3 (the merge and both lane commits). The plan's fixtures are linear, or the change is the merge itself, where the two agree. nana-pi's history has this shape: lanes merge main into themselves, then land ff-only. Fix: R-2544 and R-2545 each add an old-dated lane merged after the change (or after the tip). Assert the count equals `git rev-list --count` run in the fixture.

**M3. The count line, notes and marks can disagree with the checker in cases the plan does not test (R-2542, R-2543, D4, D5, D8).** Measured with the checker on main:
- The checker prints the count line only when the tree has field lines anywhere. A product capability with `Deliverables:` and no lines prints two notes per row and no count line. A kindless capability with one `Made by:` line prints `deliverables: 0 of 0 made and read by code` and a note. The plan's fixtures have lines on a product capability, plus a kindless ledger with none. So a build that keys the count line on listed deliverables passes.
- `deliverableFieldLinesByRow`, already exported and the obvious helper for "claims in ledger order", collects lines from every capability. A `Made by: R-100 · land: x.mjs` line in another capability's span lands under R-100. The checker calls that line unlisted and does not count it (0 of 2). A build that shows it and marks from the shown claims shows no "not made by code" mark against the count.
- The `ls-tree` call and the "paths not checked" string live in a private function in `requirements-tree.mjs`. The report would retype both. The planned test runs with git working, so a different string passes. The checker's call also has no buffer while the report's would have 64 MiB (212,915 bytes today, so this one is far off).

Fix: move the HEAD-tree read (injected runner, the buffer) and the line formatting (the count line, its gate, every note, the "paths not checked" note) into `deliverables.mjs` as one exported function. The checker prints its lines; the report shows the same array. Claims shown under a row come only from its listing capability's span. In the tests, compare with the CLI on four fixtures: lines on a product capability; a product capability with no lines; a kindless capability with one line; a kindless ledger with none. Add a runner that fails only `ls-tree`, which must give the checker's exact string. Assert one identity on the page: the items with neither mark equal the count's N, and the item count equals its M. Add a bare `land`, a bare `code`, a four-part line and a line in another capability's span to R-2542's fixture.

## SHOULD

- **S1. R-2544's trigger is narrower than its test.** "WHEN a claim names an artifact path tracked in … HEAD tree" leaves out the untracked path, yet the test asserts "age unknown: not tracked at HEAD". A build that shows nothing passes the row text. Use "WHEN a `Made by:` claim names an artifact path". The checker also accepts a folder artifact, while the walk lists files. Say whether a folder ages by any file under it or gets its own reason, and test one.
- **S2. The shallow case goes vacuous or fails on Windows.** Measured: `git clone --depth 1 <plain path>` prints "--depth is ignored in local clones" and the clone is not shallow. A hand-built `"file://" + dir` is not a valid URL on Windows (runtime-map-live's F3 lesson). Fix: clone from `pathToFileURL(src).href`. Assert `--is-shallow-repository` is true before asserting the message.
- **S3. Walk flags and parse.** A user's `log.showSignature=true` prints "Good "git" signature …" on stdout before each signed commit's record. It also verifies every signed commit, one key check each (measured with an ssh-signed fixture). `log.showRoot=false` hides a root commit's files. Add `--no-show-signature` and `--root`. `--no-renames` avoids blob reads in a blobless clone and costs nothing: 185 ms against 220 ms on main, with the same ages. Parse: each record's file list starts with a newline after the header NUL (measured). Make the test's artifact the first file listed in a commit, so a build that keeps the newline fails.
- **S4. The runtime record has a `dirty` count (`runtime-measure.mjs` line 290; this clone: 0).** A hand measure on a dirty tree is not "measured at tip X". Show "with N uncommitted files" when it is above 0, or record why not. Print the time as UTC ISO, as the impact line does (R-2528), not the raw string.
- **S5. The skill's amendment 2 still says "its consumer and check stay visible".** The owner adopted that text on 10-21. The plan deletes only the derived-consumers sentence. Say in the brief that the `Read by:` line is that consumer, so a reviewer does not read the removal as breaking amendment 2. Whether to change the owner's wording is the seat's call; the default is no edit.
- **S6. Cross-lane with suite-records (building).** That lane adds R-2547 to CAP-07's `Deliverables:` line (line 1871) and two field lines. This lane edits R-291's maker line (line 1872). Adjacent lines conflict for whichever lane lands second, and the count moves to 39. Suite records carry their own time, a second self-dated machine-local artifact. R-2545 reads only `runtime-map`, so it will show "no artifact named". Add that to the known limits.
- **S7. "Each deliverable's age" arrives for 7 of 38.** The other 31 have no tracked or self-dated artifact. File times of machine-local stores would break R-1012. The predecessor's S1 asked for this count before lane B. Put it in the land report as the trade. It is the seat's call and reversible.
