Feature: FEAT-006 · Launch builders with execution limits (R-2584 sits in FEAT-014 beside R-1100, its precedent, and is shared into FEAT-006 through Also applies)

Class: ordinary. The lane changes pi-worker (the builder launcher), new pack libs and one small check command, the builder preamble, the shared working-pattern template, AGENTS.md and the rulings text. None is on the install, hook or gate list: nana-setup is untouched, no hook or extension code changes (the rulings extension reads a file this lane edits), and review-standard.md, pi-review, review-round and nana-land are untouched. Ladder: the seat's wrong-code pairs and one final reviewer from another model family. Builder: the larger builder. Stakes: medium blast, reversible. A wrong refusal stops every lane launch on every machine until fixed; it fails closed, names its reason, and loses nothing.

Threat model: honest variation in the seat's own brief is in scope. A seat forgets the section or leaves it empty. It names a moved, deleted, staged-only or never-committed file, or writes `../`, an absolute path, a glob or a partial folder name. It uses backslash separators, backticks, a `:12` or `:12-40` suffix, or a trailing comma, semicolon, full stop or bracket. It wraps an entry onto a second line, quotes the form inside a fenced example, keeps the brief in a subfolder, or saves it with CRLF, trailing blanks, a BOM or no final newline. It names a feature with no known-bug file, or mentions another feature in prose. Deliberate forgery is out: a real but irrelevant tracked file passes. The check proves a file exists at the lane's HEAD, not that it is the right precedent. Public repo: every text in this lane names no owner and nothing about the owner's work.

Ruling: the owner, 2026-10-22. The owner reported that plans start from a fresh spec, so builders re-solve problems earlier work already solved; a later task of the same kind should reuse the earlier pattern and its fixes. The seat's audit confirmed it: no rule tells a planner, builder or reviewer to follow the nearest existing code; 0 of 364 recorded build briefs pointed the builder at its feature's known bugs; 82 of 156 lanes on this Mac needed two or more builds. The owner chose "Yes, plan it now".

The planner's draft (`plan-draft.md`) holds the code paths it checked; the adversary's attack (`plan-attack.md`, M 2, S 6, N 5) changed the plan as the decisions below say.

## Seat decisions

- **D1 · The check lives in a pure pack lib, and pi-worker calls it after brief validation (:100), before the roster, the lock and pi.** New `packages/nana-pack/lib/brief-precedent.mjs` (six-tag header, effects none): it reads the brief's Precedent section and its first Feature line, normalises each entry, and judges entries against tracked paths injected by the caller. `trackedAtHead` MOVES there from `scripts/deliverables.mjs`, which imports it back unchanged (R-2537's tests stay green). A copy would be the pattern this lane exists to stop. Every refusal goes through `laneFailure`.
- **D2 · The section reader is handoff-asks' scan, shared (adversary M2).** Move the fence-aware heading and list-entry scan out of `handoff-asks.mjs` into one shared lib module, and import it back there with no behaviour change (the frontier and report tests stay green). The Precedent section is a heading `#`…`######` named Precedent, or a plain `Precedent:` label line. Both are read outside fences only. A heading section ends at the next heading of its level or higher. A label section ends at the first line outside a fence that is not blank, not a list item and not a continuation of the entry above it. A wrapped entry is one entry. The first Precedent section wins.
- **D3 · Entry normalising (adversary M1).** An entry is `none: <reason>` (reason not blank), or a path as its first token. Strip backticks, then one trailing `,` `;` `.` or `)`, then a `:N` or `:N-M` suffix; turn `\` into `/`; drop a leading `./`. The rest of the line is a free note. A path that is absolute, starts with `~`, or climbs with `..` is refused by name without asking git.
- **D4 · Paths are checked at the lane worktree's HEAD, bounded (adversary S3, S6, N1).** pi-worker runs `git --literal-pathspecs ls-tree -z --name-only HEAD -- <paths>` from the verified worktree root (not recursive, so a folder is one entry and the output stays bounded; globs are literal), with a sealed output cap. An entry passes when a listed path equals it or holds it as a folder (`/` boundary). The refusal names every failing entry, the worktree's short HEAD sha, and the remedy: commit the file, or merge main if it landed there. A failure to list refuses with `cannot list paths tracked at HEAD`. The index and the working tree are never consulted.
- **D5 · The feature's known bugs follow the brief (adversary S2, N3).** The first line matching `Feature: FEAT-nnn` names the feature. When `<worktree>/docs/known-bugs/FEAT-nnn.md` is a regular file, pi-worker appends it as a third system prompt after the brief; otherwise none, and never `unplaced.md`. `KNOWN_BUGS_DIR` and `UNPLACED_FILE` move to a pack config module; `scripts/known-bugs.mjs` imports and re-exports both, so its importers and R-2509's seal are unchanged (UNPLACED_FILE moves only to keep the pair together). One launch line before pi starts: `pi-worker: precedent: <N> checked at HEAD <sha>; known bugs: <worktree-relative path | none>`, where N counts every entry, path or none.
- **D6 · Two preamble lines (adversary S2).** Under Scope: a builder reads every file its brief's Precedent section names before designing, follows its pattern, and reports each departure with its reason. And: the known bugs that follow the brief are context; fix only those the brief names, and report each one the change touches.
- **D7 · A check command now, for the Claude Code builder path (adversary S1; the planner's default `later` is overruled).** 96 of 378 recorded build briefs went to a Claude Code subagent, which pi-worker never sees. `packages/nana-pack/bin/brief-check.mjs --brief <file> --tree <worktree>` runs the same lib calls pi-worker runs and prints the same refusal or the same launch line, starting nothing. It runs through node from the checkout, so nana-setup and PATH stay untouched. AGENTS' Larger-lanes sentence for a Claude Code entry gains: the seat runs brief-check on the brief first.
- **D8 · The plan line and the ruling.** The shared template's Plans bullet gains one sentence after the threat-model sentence: every plan names its precedent, the nearest existing code for each part by path, or none with a reason. AGENTS.md's marker region stays byte-identical (R-859). The local brief section (AGENTS.md "The tree in briefs, reviews and lands") gains one sentence: a lane brief carries a Precedent section, and pi-worker refuses one without it. The ruling lands as text with no row, as every ruling has (R-1415 to R-1417 pin the shape): `- 2026-10-22: Every plan and brief names its precedent, the nearest existing code for each part. Builders follow it and report each departure. pi-worker refuses a brief without it.`
- **D9 · Left out.** The review-standard clause (`no`): its first line already makes every non-MUST finding a known bug, it is the text pi-review appends (a review-tool change), and the builder's departure report already reaches the seat. A size guard on the attached known-bug file: the largest is 46,035 bytes, under one read window; recorded as a known limit. Old briefs in docs/reviews are records: no scan, no migration.

## Amendment 1 (seat, after build 1)

The seat ran build 1's reader on this lane's own `build-brief-1.md`: a plain `Precedent:` list, a blank line, then the numbered steps. The reader took steps 1 to 4 as entries, so pi-worker would refuse the brief, naming "Move", "brief-precedent.mjs", "Update" and "Run". D2's label rule caused it: it skipped blank lines inside a label section. That is the standard seat brief shape, so honest briefs fail.

D2 now reads: a label section's entries are one block. It ends at the first blank line after its first entry, at a heading, or at the first line outside a fence that is not blank, not a list item and not a continuation of the entry above. A heading section keeps its rule. R-2580's table gains a case: a label section, a blank line, then a numbered step list; it passes, and N counts only the section's bullets. Known limit added: a loose list (blank lines between bullets) under a plain label loses the entries after its first blank line, which go unchecked; use the heading form for a loose list. Wrong-code pair added: the label section continues past a blank line.

## Known limits (the seat writes them to the FEAT-006 known-bug file before the final round)

- Existence, not relevance: a real but wrong tracked file passes (outside the threat model).
- HEAD is the lane's: a file moved or deleted on main after the branch point still passes, and a precedent that landed on main after it is refused until the lane merges main.
- A Claude Code subagent builder gets only what the seat runs: brief-check is advice the seat follows, and that builder gets no preamble and no known-bug attachment.
- The brief is read once at launch; an edit after launch is not checked. The first Precedent section and the first Feature line win.
- Paths only: a commit or a review finding goes in an entry's note after a tracked path, or as `none:`. Line suffixes are not checked against the file. Path case must match git's.
- On POSIX a tracked file whose name holds a backslash cannot be named.
- A loose list under a plain `Precedent:` label loses the entries after its first blank line; they go unchecked. The heading form keeps a loose list whole.
- No size guard on the attached known-bug file; the largest today is 46,035 bytes, under one read window.
- No tool reads the builder's departure report; it reaches review when the seat puts it in the review brief.
