**D1 — FINDING (MAJOR).** The core RPC seams exist: the desk exposes spawn/events/prompt/RPC/UI-response (`apps/desk/server.mjs:26-33`), forwards arbitrary child events (`server.mjs:234-257`), and RPC tool completion includes `result.details` (`docs/rpc.md:1012-1051`); dialogs work in RPC mode (`docs/rpc.md:1184-1205`), and `renderCall`/`renderResult` exist for TUI rendering (`docs/extensions.md:2240-2242`). Two claims overstate the implementation: `/api/live` only enumerates process-local children by id/cwd and provides neither app identity nor unique reattachment policy (`server.mjs:988-995`), so “one session per app instance, reattached on reload” is application logic not an existing guarantee; and the desk renderer is not reusable as a module—`toolRow`, `finishToolRow`, and `handleEvent` are private globals (`apps/desk/public/app.js:349,393,861`) with no exports. It must first be extracted/refactored, not merely reused as claimed in the design (`agent-frontend-design-2026-09-04.md:60-61`).

**D2 — FINDING (BLOCKING).** The central ref-table tooth is not implementable across the claimed tools as written. `nana-present` says it “registers nothing else” while exposing `registerRef()` to app MCP/extensions (`agent-frontend-design-2026-09-04.md:106-107`), but pi provides inter-extension communication only through mechanisms such as the shared event bus (`docs/extensions.md:1727-1733`); an out-of-process MCP server cannot call a TypeScript extension function. The existing family-planner tools return raw HTTP strings (`family-planner/mcp_server.py:42-50,54-56,246-248`), not `{data, ref}`, and therefore register nothing in a pi-session table. Pi-extension query wrappers could share a registry, or `nana-present` could intercept declared tool results, but that is a different architecture. Even then, the model still authors `projection`, title, labels, narrative, row selection, and inline data (`agent-frontend-design-2026-09-04.md:94`), so the design prevents retyping only if projection is a closed deterministic operation; it does not currently prevent misleading labels, selective omission, invented derived values, or fabricated narrative.

**D3 — FINDING (MAJOR).** The lifecycle answer holds only for compaction while the same extension runtime and browser remain alive. Browser reload receives dialogs/status/widgets in `desk_hello`, not stage blocks (`apps/desk/server.mjs:1021-1027`), and the server explicitly does not replay events (`server.mjs:40-43`); reconstruction would need a specified durable block ledger and `get_entries`, which uniquely includes pre-compaction history (`docs/rpc.md:717-719`). Extension reload, session replacement, fork, and resume tear down and recreate extension state (`docs/extensions.md:432-450,1318-1320`), while desk restart recreates the in-memory child map and kills children on shutdown (`server.mjs:116,1250-1253`). The documented persistence mechanism is `appendEntry()` or reconstructing state from tool-result details (`docs/extensions.md:1471-1482,1877-1879`), but the design uses neither for refs. Consequently refs, stage state, and app-to-session association are lost or ambiguous after reload/restart/death, and “source expired” itself cannot reliably be determined from the current client-only stage (`agent-frontend-design-2026-09-04.md:109,143`).

**D4 — FINDING (MAJOR).** Six visual primitives plausibly cover screenshots, but that does not establish transferability of interaction, evidence, or lifecycle semantics. AML needs cell-level evidence/provenance, graph expansion and potentially hundreds of nodes; family-planner needs authenticated mutation and refresh; basketball needs league/roster semantics. Declaring success unless AML needs a seventh block tests taxonomy, not whether the mechanism transfers. The proposed first slice is especially weak: it avoids existing MCP interoperability, durable mutations, attribution, authz, gate visibility, multi-user behavior, and large graphs—the exact risky seams. Its stated data basis is also ahead of the listed source: the README documents only the Stage-1 NBA pipeline and `data/basketball.sqlite` (`basketball-geek/README.md:3-15,34-38`), not `intel.sqlite`, boards, league imports, roster ownership, or trade-candidate semantics assumed by the slice (`agent-frontend-design-2026-09-04.md:121-132`). It can judge visual feel, not the kit’s three-product claim.

**D5 — FINDING (MAJOR).** The design front-loads six block renderers, three chart types, graph layout, dual browser/headless output, TUI fallback, a shared ref protocol, a drawer, attribution hooks, and scheduled-turn support before validating one useful path (`agent-frontend-design-2026-09-04.md:68-96,127-130`). The ref table in particular does not earn its cross-process lifecycle cost. A smaller proof is: one app page, extracted RPC client/dialog layer, two blocks (`table` and `card`), and app-owned query tools that return a fully materialized validated block in `details`; persist presented blocks in session entries and generate HTML from that ledger. If stronger provenance is required, make `present` accept a closed `{queryTool, queryResultId, projectionId}` capability or have query tools emit blocks directly, rather than exposing a general model-authored projection over an ephemeral registry.

**D6 — FINDING (BLOCKING).** “No new privilege” is false. `/api/spawn` accepts arbitrary existing cwd, extension paths, appended system prompt, and `approve` (`apps/desk/server.mjs:997-1009`), while resource narrowing disables only skills/extensions—not pi’s built-in filesystem and shell tools (`server.mjs:128-153`). The desk has no authentication, origin check, per-app session ownership, or CSRF protection shown, and `/api/live` exposes every child rather than an app-scoped child (`server.mjs:988-995`); proxying it through a phone-facing backend could expose machine-level agent control and cross-app transcripts. Family-planner uses one process-wide bearer token (`family-planner/mcp_server.py:35,39`), so drawer identity is not intrinsically bound to the token owner, and the tool set includes broad mutations (`mcp_server.py:169-190,194-201,209-228`). Finally, putting gate dialogs inside a collapsible drawer is weaker than a top-level invariant: pending gates must occupy an always-visible, non-foldable surface and fail closed when no client is attached; badge-plus-auto-open (`agent-frontend-design-2026-09-04.md:153`) does not cover headless scheduled turns, disconnected phones, competing clients, or dialog timeout behavior.

**VERDICT: REWORK**

1. Define an enforceable provenance contract: where refs are minted, how MCP results enter it, a closed projection language, and exactly which fields remain model-authored.
2. Make refs and presented blocks session-durable and specify deterministic recovery across browser reload, compaction, extension reload, desk restart, and child death.
3. Add authenticated, origin-checked, app-scoped desk capabilities; prohibit arbitrary cwd/resources/approve and disable unrelated built-in tools for app sessions.
4. Put pending gates in an always-visible host surface and test fail-closed behavior with collapsed, disconnected, reloaded, and headless clients.
5. Extract a supported RPC/dialog/tool-row client module; add stable app/session identifiers rather than matching `/api/live` by cwd.
6. Reduce slice 1 to a two-block vertical path, then make slice 2 exercise MCP interop, mutation refresh, evidence provenance, and lifecycle recovery before claiming transferability.
7. Reconcile the basketball slice with data that demonstrably exists, or explicitly add the missing roster/intel/league adapters as dependencies.
