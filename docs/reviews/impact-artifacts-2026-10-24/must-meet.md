## Seat decisions

- **One record shown.** The block reads only `Artifact:` writer lists and `Reads:` lines, joined to the import graph each time it runs. Deliverable `Made by:` and `Read by:` lines also name makers and code readers for 23 artifacts; this lane does not join them (the ledger reader-lines lane decides where those readers live), and the closing note says so. Nothing goes into `docs/code-map.md` or any module header; a ledger edit never makes the map stale.
- **Seam.** The block is one exported async function in the shim, `artifactBlock(root, argv, { load })`, beside `runtimeBlock`. It reads `REQUIREMENTS.md` under `root`, builds one graph from `root` and passes it to path resolution and the radius, resolves the arguments as the generator does (the shim's `resolveImpactPaths`), and gets the parse modules from `load`. The default `load` is a caught `import("./requirements-tree.mjs")` and `import("./deliverables.mjs")`, written as literal relative specifiers so the map shows both edges and Windows resolves them. The import runs only inside this function, never at module top, because `scripts/requirement-rows.mjs`, `scripts/blast-radius.mjs` and `scripts/template-acceptance.mjs` import the shim. The CLI tail awaits it between `main` and the runtime block and keeps its synchronous `process.exit`: a natural end prints Node's `MODULE_TYPELESS_PACKAGE_JSON` warning, which would break R-1272 and R-1273.
- **Order:** generator output byte for byte, then the artifact block, then the runtime block. R-1272's and R-1273's wording and R-1272's test title gain the block's place.
- **What the block shows:** for each named file, the artifacts its path appears on as a writer, with every recorded reader and a mark on readers outside the file's import radius, and the artifacts it appears on as a reader, with a star when no recorded writer is inside its radius. Import radius means the file plus its transitive callers and callees from the generator's `impact`, computed per named file.
- **No "one import away" line** (subtraction): it over-credits shared codecs and adds noise.
- **No key check.** A ledger path that is not a mapped module never joins an import radius, so the block marks it `(no import path)` or `*`, which is true. Today 57 of the 61 ledger paths are mapped, one is ignored and three are not modules. The design's R-2824 is dropped.
- **Labels are contract values** in `packages/nana-pack/lib/runtime-map-config.mjs`, whose purpose sentence widens to "the runtime map and impact command's tunables"; they stay importable without the parse chain, so R-1278's copied config keeps working. One seal pins every label.
- **`no live entry`** follows the product report's display; if the builder lifts that text into `scripts/deliverables.mjs` as a constant for both, the move is named in the build report.
- **Not in this lane:** the audit's ledger reader lines (`source`, artifact `Read by:`, `Parked:`, `by:` for hand-run makers), joining deliverable lines, a file that is itself an artifact's location, and any page change.

## Known limits (the seat writes them before the final round)

- The block shows only `Artifact:` writer lists and other features' `Reads:` lines: own-feature readers, deliverable `Read by:` readers, hand-run makers, people and outside tools do not show until the ledger reader-lines lane. For example, impact on the runtime measurer does not list the impact command as a reader.
- Naming an artifact's own file, such as REQUIREMENTS.md, HANDOFF.md or the review standard, lists none of its readers.
- A shared codec that writes for its callers, such as the record-ledger module, shows no artifact; the ledger names the caller.
- A file that starts reading or writing a store with no ledger line shows nothing.
- `(no import path)` is mostly benign: install checks, presence checks, git-owned formats, spawned commands and CI.
- The block depends on agents running the impact command and reading it.
- The parse chain loads a TypeScript module, so the block needs Node's type stripping (Node 22.18 or later); on an older Node it prints the artifact note every time.
- Other projects get nothing: the templates ship no ledger parse.
