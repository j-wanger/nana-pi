**SHOULD / NOTE (known-bug candidates for FEAT-006)**
1. **NOTE: a `no end` build can absorb a later plain run's cost.** An unpaired start that is the last start in its session folder has no end to its time window. A later plain (non-lane) pi-worker run in the same worktree also names its sessions `pi-worker-a…`, so its cost would be added to the `no end` build. The trigger is a hard-killed lane build followed by a plain run in the same worktree, which is rare.
2. **NOTE: one unreadable file in the session folder makes the cost unknown.** In `collectBuildUsage`, a failed head read on any `.jsonl` file inside the time window gives a null cost for the whole build. This happens before the path and name filters could skip that file. Examples are an unreadable reviewer session, or a folder whose name ends `.jsonl`. D4 wanted an unrelated session never to cost the build its price. The fix is to skip a candidate whose head cannot be read, rather than giving up. Records only, no build impact.
3. **NOTE: every build end reads sessions for every killed build in the clone.** `buildEndLine` calls `renderLaneLine` on the raw records of the whole ledger. That pairs every lane and runs `collectBuildUsage` for every unpaired start in every lane, not just this one. Each time window is bounded, so the cost grows with the number of killed builds, but the end line only needs this lane. Filtering the records by lane before pairing would make it cheaper.
4. **NOTE: an unknown outcome reads as `failed` without a count.** `buildViews` maps an outcome it does not know to `failed`. That only happens under a future schema 1 writer, so it is out of scope today.
