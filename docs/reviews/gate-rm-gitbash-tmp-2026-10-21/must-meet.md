It reopens the rm-outside-asks lane's known limit 7 (`docs/reviews/rm-outside-asks-2026-10-20/must-meet.md`) and closes the HANDOFF residual on the Git Bash `/tmp` block and the rm-outside-asks round-1 SHOULD 2. Class: install, hook or gate (it changes the nana-gate policy's reading). Ladder: the roster's reviewer and land reviewer on the exact final tip, the seat's wrong-code pairs, one independent check, the macOS install check before the land.

Threat model. In scope (honest variation): the Git Bash spellings an honest builder or reviewer types on native Windows — `rm -f /tmp/out.txt`, `rm /tmp/sub/*.log`, `cd /tmp && rm x`, `pushd /tmp/sub`, `/c/...` and `/C/...`, `cd /c/<worktree> && rm -f x` (models copy Git Bash's `pwd`); TMP and TEMP differing, one unset or empty, or written as 8.3 short names; a TMP at a drive root, the home folder or above home; a link inside the temp folder that leads outside; a `..` that climbs out of `/tmp`; lookalike names (`/tmpx`, `/tmp2`, `/cd`); PowerShell's own `/tmp`, which means `\tmp` on the current drive; macOS and Linux, which must not change; Linux CI, where the test fixture root lies under `/tmp`. Out (deliberate forgery): a TMP or a Git Bash fstab set up to hide an outside folder, eval or base64, a race that swaps a folder for a link, a command prefix, BASH_ENV or spawn hook that changes the shell. The gate is advisory by load path.

Security floor: the translation runs only inside the rm-outside reader, which only adds non-floor asks (`markOutside` sets `floor: false`). The floors stay exactly as they are. The translated path meets the unchanged containment rule (realPath of the parent, the strict-inside test, the shared rule's drive-root and home exclusions), so a folder counts as temp only if the shared temp-folder rule already accepts it. Under Git for Windows' default mount table the translation matches Git Bash for absolute spellings once `.` and `..` are collapsed first; under another bash or a hand-edited fstab it does not (known limit).

## Facts (verified 2026-10-21)

- Git for Windows appends `none /tmp usertemp binary,posix=0,noacl 0 0` to `/etc/fstab` (git-for-windows/build-extra `git-extra/git-extra.install.in:116-118`). msys2-runtime fills a usertemp mount from GetTempPathW, which reads TMP, then TEMP, then USERPROFILE, then the Windows folder.
- `none / cygdrive` makes `/<letter>` a drive; msys2-runtime `mount.cc` `cygdrive_win32_path` (:895-917) accepts one letter of either case, followed by `/` or the end, and upper-cases it.
- On main nothing reads these spellings. On win32 `path.resolve` turns `/tmp/out.txt` into `C:\tmp\out.txt` and `/c/Users/u/x` into `C:\c\Users\u\x` (`gate-rm-outside.ts:101`, `:157`); both are outside, so a headless rm blocks (`nana-gate.ts:375-376`). `gate-temp-roots.ts:104-110` accepts only tmpdir plus win32 TMP.
- pi on native Windows runs bash through Git Bash first (pi `docs/windows.md`, `dist/utils/shell.js` `getShellConfig`).
- CI runs only on a push to main and on pull requests: the Windows leg needs a draft pull request.

### What each test does

Helpers the builder adds: `gbHits(command, { platform = "win32", env = { TMP: TEMP_ROOT }, tool = "bash", tempRoots = [TEMP_ROOT] } = {})` (moduleHits plus platform and env); in session 2 a link `TEMP_ROOT/linkout` → OUTSIDE (a junction on win32, the file's linkType); in session 3 `gitBash(p) = "/" + p[0].toLowerCase() + p.slice(2).replaceAll("\\", "/")`. On Linux the fixture root lies under `/tmp`: never type a fixture's absolute path as a target in a win32-injected check; spell targets as `/tmp/...` or relative paths.

- **R-2490.** env {TMP: TEMP_ROOT}: `rm -f /tmp/out.txt`, `rm /tmp/sub/x` and `rm -f /tmp/sub/*.log` each give 0 hits; `rm -f /tmp` gives exactly `[TEMP_ROOT]`. env {TEMP: TEMP_ROOT}, {TMP: "", TEMP: TEMP_ROOT} and {TMP: TEMP_ROOT, TEMP: OUTSIDE}: `rm -f /tmp/out.txt` gives 0 hits. env {TMP: OUTSIDE, TEMP: TEMP_ROOT}: exactly `[path.join(OUTSIDE, "out.txt")]` (TMP before TEMP). env {}: exactly 1 hit.
- **R-2491.** env {TMP: TEMP_ROOT}: `cd /tmp && rm -f out.txt` and `pushd /tmp/sub && rm x` give 0 hits; `cd /tmp && rm ../x` gives exactly one hit.

## Design

1. `lib/gate-rm-outside.ts`: the three constants and a named export `gitBashPath(spelling, { platform, env }): string`. Not win32, or env missing → unchanged. A spelling that begins with `//` or holds a backslash → unchanged. Otherwise `path.posix.normalize` it first (as Git Bash collapses `.` and `..` before its mounts), then: exactly `/tmp` or starting `/tmp/` → the first non-empty of env.TMP, env.TEMP, followed by the rest exactly as typed (neither set → unchanged); `/<letter>` then `/` or end → upper-cased letter, `:`, then the rest or `/` (so `/c` → `C:/`, never drive-relative `C:`); else unchanged. Text substitution only, never path.win32 (macOS checks feed POSIX fixture folders through it).
2. `rmOutsideTargets` options gain injected `platform` and `env`; absent means no translation (moduleHits keeps today's reading).
3. `placedTarget` (:97-101), bash only: translate the typed target before `homeExpanded`; the home expansion itself is not translated. The cd branch (:155-157), bash only: the same for `typed`.
4. `extensions/nana-gate.ts:148-152`: add `platform: process.platform, env: process.env` to `outsideOptions` — pass the live `process.env` itself, never a spread copy (only the live object looks names up case-insensitively on Windows).
5. Headers (`gate-rm-outside.ts` @inputs/@outputs; the test file's counts and @effects naming the Git Bash spawn R-2497 adds), `npm run map`, the README rm-outside bullet's Git Bash rule and known limits, and the three wording fixes.

## Known limits (carried to HANDOFF)

- Other shells (Cygwin, standalone MSYS2, legacy WSL, a shellPath) or a hand-edited fstab: `/tmp` is that shell's own temp folder and `/c/` is not a drive, but the gate still reads Git for Windows' spellings.
- Git Bash fixes `/tmp` once per user while any Git Bash process runs (one mount table per user); a Git Bash started earlier with another TMP decides it, while the gate reads pi's own TMP and TEMP (read from source, not run).
- The TMP-before-TEMP order rests on the runtime source and GetTempPathW's docs; CI cannot test it. The claim most likely to be wrong.
- After `cd /tmp`, a relative `..` above `/tmp` is read under the temp folder's parent, while Git Bash reads it under its install root (it asks either way).
- Other Git Bash root paths (`/usr/…`, `/etc/…`, `/home/…`) are read on the working folder's drive; they ask, naming a path Git Bash would not delete. `/cygdrive/c/…`, `/mnt/c/…` and `//host/…` are not read as drives, so they ask. Only lowercase `/tmp` is read. With neither TMP nor TEMP set, `/tmp` asks.
- Recursive and forced forms (`rm -rf /tmp/build`) keep today's ask (the rm-inside exemption rejects absolute targets).
- The nana-gate wiring is pinned by the Windows CI leg alone.
- Separate residual, not this lane: the rm floor's root check (`lib/gate-shell.ts:195`) does not count a Git Bash drive root such as `rm -rf /c/` as a root or home ancestor; a non-floor ask today, so an owner allow pattern could exempt it.
