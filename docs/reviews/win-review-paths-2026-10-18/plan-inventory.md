INVENTORY: path-spelling sites in the land and review tools (nana-pi main at 2eb0cb8; read-only, nana-pi tree still clean)

Class codes: C = letter case, S = 8.3 short name, F = forward vs back slash, Q = `\\?\` prefix, D = lowercase drive letter, L = symlink spelling (a sixth class, already live on POSIX).
Evidence tags: [mac] = confirmed today by a probe on this Mac (scratch repo at <seat-scratch>/pathprobe); [CI] = seen in a Windows CI log quoted in w7-triage.json; [inf] = inferred from code or path.win32 behaviour, not run on Windows.

The pattern behind every site: one operand comes from git, which is already in its canonical form. On macOS that comes from getcwd; on Windows it is the long form with forward slashes [CI]. The other operand comes from a user flag, the cwd or tmpdir(), and goes through JS realpathSync (which keeps the typed case, 8.3 names and drive case) or through no realpath at all. Two shared helpers carry most of it:
- `relUnder` (review-round.mjs:241-246) uses the platform's path.relative. On POSIX that is case-sensitive and does not resolve symlinks. On win32 it ignores case and slash direction [probe of path.win32], does not expand 8.3 names, and returns an absolute path for Q or a different drive, which relUnder reads as "outside".
- `realOut` (review-round.mjs:250-252) uses JS realpathSync.

- pi-watchdog.mjs:161: the capture temp folder is never compared.
- review-shape.mjs has no paths.

**Persisted keys** (a spelling change orphans records)
- The tally is `<home>/.pi/agent/review-ledger.rounds.jsonl`. It is deliberately not pi's active agent dir (review-round.mjs:84), it never rotates, and its `repo` field is read by R2, N2 and L1.
- Reservations are `<home>/.pi/agent/review-ledger.reservations/<id>.json`. Each holds `repo`, `cwd` and `exclude`; they are short-lived, but N2 reads them for R-1006.
- The audit log is `review-ledger.jsonl` plus `.1`. It holds `repo` but nothing reads it for decisions.
- This Mac today: 813 tally lines and 9 distinct keys (6 `git:`, 3 legacy `path:`). No key differs by case alone. For every key whose path still exists (3 no longer do), both JS and native realpath equal the stored spelling. Switching macOS to native would orphan nothing here.
- On Windows seats, pi-review keys come from git's long form, so they stay stable. Keys written by review-ledger run/check from an 8.3, mis-cased or lowercase-drive main checkout would change, so those items restart their round count once.
- Adding win32 case-folding (the adoption.mjs:76 pattern) changes every existing Windows key once.
- R2, N2 (:78) and L1 must move together on one function. Otherwise nana-land stops seeing review-ledger-run records, or the reverse.

**Deltas vs the cut (lane 3) and the attack**
1. Attack MUST 1 is confirmed on macOS by probe for N1, N3 (API path), R2, R3 and R6.
2. A seventh macOS harm is live today through the symlink class, which none of the five classes name:
   - P1, P7 and P5 never realpath `outPath` or `tempRoot`.
   - P5 is vacuous under the default macOS TMPDIR.
   - P1 and P7 give an extra round for an `--out` spelled through /tmp or /var.
   - The cut's `realOut(outPath)` at :159-161 fixes P7 only. P1 (:70) and P5 (:117) need it too, or the fix goes inside workingState's skip (attack SHOULD 1).
3. relUnder already handles Windows case and drive letter (win32.relative ignores case). Only the plain `===` and `includes` sites break on C and D: N1, N2/R2/L1, N3, P5 and P6.
4. P3 (:92) and P7 (:162) have no isAbsolute check. A `\\?\` path or a different drive reads as "inside".
5. N3 cannot be reached with two spellings from the CLI. A test for it must call the exported `runCleanup`.
6. Changing R1 (:161) or P2 (:72) is a no-op. The fix belongs on the user-side operands: realOut, outPath, tmpdir(), and the tree spelling joined to a relative `.git`.
