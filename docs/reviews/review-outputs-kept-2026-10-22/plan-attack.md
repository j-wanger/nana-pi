## Q1 answer in short
Both real callers already hold the text: pi-review writes `r.text` to --out then calls complete (pi-review.mjs:220-221); run decodes the child's stdout to a string, writes it, then calls complete (review-ledger.mjs:105-113). Tests pass the verdict string itself as `out` (land.test.mjs:44, path-spelling.test.mjs:461). So text and file differ only when something rewrites --out between the write and the locked read, e.g. two reviews sharing one --out path. The seat wrapper names outputs by basename under the item folder. Keeping the captured string is right and matches R-2568/R-2569. A reviewer that writes --out with a tool is overwritten by the launcher, so the kept text is still what the verdict was read from.

- **M2 · "The LAND record nana-land relies on" is undefined, and a missing text can block a revision for good.** The land accepts if *some* verified LAND matches (nana-land.mjs:94). An install, hook or gate lane has two LAND records on the tip (final reviewer and land reviewer), and a same-revision re-review adds more. If the rule is "every matching LAND", one deleted text blocks that revision for good. The tally is append-only, and a re-review of the same revision adds a record but cannot remove the bad one. Recovery then needs a new commit and a new round, possibly over the cap. Pin the set in R-2571, with a two-record test (one intact, one missing). Put the recovery in the refusal text and the Trust model. Default reading of the ruling: every matching LAND, refusal names the recovery.
- **M3 · "A failed write records nothing" has no row, and under M2 it decides whether a revision can ever land.** If the builder writes the text best-effort and records anyway, the tally gains a hash whose file is missing, and that revision is refused for good. Add a row with a cross-platform test: make `review-ledger.texts` a regular file, so ensureDir throws (review-round.mjs:376-380). Assert no tally or audit line, ok:false, and the --out path named. Wrong-code pairs: the tally is appended before the store write; the record is kept when the store write fails.
- **M4 · The lane-folder copies come from a hand-run step, against the 2026-10-22 rulings line.** That line says "Closing a hand-made maker or a rule-only reader comes first". `keep` runs only because an AGENTS clause tells the seat to run it, and nothing checks that the non-final texts reached the tip. Option one is cheap and deterministic: nana-land prints one note per kept text of a named item, from a non-landed revision, whose git blob id is not in `git ls-tree -r <tip>`. Option two is better: the same check as an admission warning, so the seat can abort the final round before it is spent. At the least, add a CAP-02 line "Made by: manual" for the lane-folder copies and carry the gap. Default: land note.

## S (should)
- **S1 · Hash fixture.** run decodes stdout with `toString('utf8')` (review-ledger.mjs:105), so the raw bytes are the UTF-8 encoding of the captured string, not the child's raw stdout (invalid UTF-8 becomes U+FFFD). Say so in the row. The R-2568 fixture needs a BOM, CRLF line endings, trailing blank lines and a non-ASCII character. Without them, pair 3 (trim or BOM strip), CRLF normalising and latin1 encoding all stay green.
- **S2 · Store write mechanics.** (a) Make the temp file in the store folder itself. A temp in os.tmpdir() breaks with EXDEV on a Linux tmpfs, the leg that does not block release. Test: run complete with TMPDIR, TEMP and TMP pointing at a missing folder. (b) On win32, retry the rename on EPERM, EBUSY and EACCES, because antivirus holds new files. Prior art: renameWithRetry at nana-setup/lib/project.mjs:252, which nana-pack must copy, not import. (c) An existing `<sha>.md` with other bytes is corrupt by definition. Refusing it leaves every later identical text unrecordable, the empty text included, so replace it.
- **S3 · Which home `keep` reads.** review-ledger.mjs:54 and review-timeline.mjs:140 read `HOME ?? USERPROFILE`; complete and land use os.homedir() (review-round.mjs:715, nana-land.mjs:71). On Windows, os.homedir() reads USERPROFILE. With a Git Bash HOME that differs, `keep` reads another ledger and writes nothing, silently. Have `keep` use homedir() and exit 1 when the item has no kept text.
- **S4 · Accepting legacy records has no row, yet another lane depends on it.** claude-review-launcher rounds recorded before this lane lands carry no hash; a builder that refuses those blocks that lane. Add cases: no `text` key lands with a note; a `text` key with a malformed sha256 or bytes value refuses. Pair: a malformed `text` treated as legacy.
- **S5 · R-2574's ordering.** Put the differing file under the *last* name keep would write. Otherwise a keep that checks each name as it writes passes "writes no file".
- **S6 · Writing into the lane folder during a live review.** review-ledger run re-derives the revision in the live tree (review-round.mjs:735, `r.cwd`); pi-review re-derives in its own checkout. With Claude as the fleet's final reviewer, a `keep` into the worktree while that review runs marks it unverified and uses the round. Option: refuse when a live reservation's tree contains `--into`. At the least, add it to known limits.
- **S7 · The land-checklist clause is in the shared marker region.** It sits at AGENTS.md:68-103 and comes from templates/_shared/working-under-nana-pi.md:29. Edit the template, regenerate, and expect templates-render, project and entry-guidance tests to move. The clause ships to every scaffolded project.
- **S8 · R-1561 needs rewording too, not only R-1562.** Its condition is "the ledger recorded the file". Also update review-timeline's @inputs header (review-timeline.mjs:6-8).
- **S9 · Real Windows proof.** The install check already runs pi-review in a temp home on macOS and on Windows through cmd and Git Bash (install-check-config.mjs:107-122). Extend judgePiReview (install-check.mjs:264) to require the tally's kept text to equal the review text. That is the only real proof of the store write on Windows.
