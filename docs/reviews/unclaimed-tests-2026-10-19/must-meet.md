# unclaimed-tests — must-meet

Feature: FEAT-028 · Maintain requirement identity and trace links
Class: ordinary (template trace rails, nana-pi's trace shim, the requirements skill; no install, hook, gate, land or review tool). Built by the larger builder: two languages, four modules.
Threat model: honest variation in our tools' output, platforms (macOS, Linux, Windows; CRLF, trailing space or tab, no final newline, nested test folders) and project configs (call names, test roots, decorators) is in scope. Deliberate forgery is out: a declaration hidden from the grammar on purpose is a residual.

Feature sentence: with `NANA_REQ_UNCLAIMED=1` set, the trace rail lists every test declaration that no `req:` marker claims, by path, line and title, and nothing else about the run changes.

## Design
- Switch: environment variable `NANA_REQ_UNCLAIMED`, on only at `1`; each rail names it `UNCLAIMED_ENV` (a contract value, sealed by R-1665). Off, every output stays byte-identical to today. Opt-in because nana-pi alone has 2,103 unclaimed declarations of 5,070 (measured 2026-10-19).
- A test declaration is a line the rail's marker grammar can bind. TypeScript: a line of a test source (TEST_EXTENSIONS under the test roots) on which the rail's call pattern for the configured call names matches (quoted title on the same line; first call on the line wins). Python: a `def test…(` line (any indent, async allowed) or a test/it/check call with a quoted title, in `test_*.py` under the test roots.
- Claimed means the rail's own binding: a marker block directly above, and in Python also across decorator lines. Build it from the rail's existing pieces (marker regex, id reader, call pattern, BOM strip, line-end trim). `check()`, `scanSource` and `scan_source` keep their return shapes.
- Listing line 1, always, even at zero: `unclaimed: <N> test declarations carry no req: marker`. Then one line per unclaimed declaration, `  <path>:<line> <title>`, ordered by path, then line. The path is project-root-relative with `/` on every platform, compared as one whole string: not folder-walk order, not Python `Path` order.
- No grouping by nearby row (amended). A 10-line window holds 70% of nana-pi's unclaimed declarations, but 11% in an adopted TypeScript project and 25% in an adopted Python one (measured 2026-10-19). The audit serves adopted projects, so the window would put most lines under "no nearby row" and cost a sealed tunable in two rails.
- Surfaces. The TypeScript rail exports `unclaimedLines(root, options)` (the listing as lines) and `printUnclaimed(root, options, env)`. nana-pi's trace command calls `printUnclaimed` after its problem lines and ends by setting `process.exitCode`, not by calling `process.exit()`: Node drops pending stdout writes on exit (probe: 40,000 lines then `process.exit` delivered 3,841 through a pipe on macOS; `process.exitCode` delivered all). The rendered project's status test calls `printUnclaimed` after `printReport`. Python's `pytest_sessionfinish` writes the listing after its own lines when the switch is on, through a helper. It never touches the exit status and prints no listing when `check()` raised.
- Skill: one paragraph in §5 between Pass 1 and Pass 2.

## Known limits
- The grammar is the rail's own. A call whose title starts on a later line, `test.skip(`/`it.each(` forms, and pytest tests outside `test_*.py` are not declarations. A declaration-shaped line inside a string or comment is listed.
- One line per declaration, not per generated case: a loop or a parametrize is listed once.
- `req-candidate:` claims nothing, so an adopted project's template tests stay listed until the audit promotes their rows.
- No nearby-row hint: the auditor opens the file at the listed line to see its neighbours. nana-pi's own 2,103 lines come unsorted by likely row.
- A zero count means no declaration the grammar can see is unclaimed. It does not mean every behaviour has a row.
- A Python project with no rows, no markers and no problems prints nothing, listing included (the hook's existing early return).
- Paths holding characters outside the Basic Multilingual Plane may sort differently between the rails. Titles with escape sequences may print differently, as in the trace today.
- The rendered TypeScript project's status test call runs only in a rendered project (release acceptance). nana-pi's suite pins `printUnclaimed` through the trace command, which calls the same function.
