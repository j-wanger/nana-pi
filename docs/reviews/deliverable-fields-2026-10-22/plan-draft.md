# Lane plan draft: deliverable-fields (main 08c33d94)

Probe: `git archive` copy of main, `git init`, temp HOME; single test files only. Ages and file lists probed read-only on main. "Deliverable" means a row on a `Deliverables:` line (38 here).

## 1. What the lane changes

Each deliverable on a live `Kind: product` capability gains two optional, repeatable lines in that capability's span: `Made by:` names the run that makes it, `Read by:` names the code that reads it, or `manual`, `rule` or `person` with a reason. A report-only check lists notes: a missing reason, a path git does not track, a missing or unreadable line. The tree checker command prints the notes and keeps its exit status. nana-pi's 38 deliverables gain their lines. The product report's age and reader column follows in lane B (section 4).

## 3. Decisions

- **D1 Field shape.** (a) Lines in the capability span after `Deliverables:`, one line per maker or reader, any order. (b) A cell in the row table: every parser pins the four-column header. (c) Lines in the home feature's span: they move with a regroup, but the five fields are never read in a feature span. (d) A separate section or file: fails "in place". Recommend (a). Default: `span`.
- **D1a Grammar.** `Made by: <row> · <run>[: <detail>][ · <artifact>]` and `Read by: <row> · <reader>[: <detail>]`. Runs: `session start`, `suite`, `land`, `review`, `build`, `CI`, `hook`, `extension`, `manual`. Readers: `code: <path>[, <path>]`, `prompt` (the maker puts it in the agent's context), `person`, `rule`. `manual`, `person` and `rule` need a reason. The artifact is a repo-relative `/` path, or `runtime-map`. A row may carry several lines of each (the install check is made by CI and by hand). Read only on a live `Kind: product` capability; prose elsewhere, as cap-kinds did. Inferred from the audit: `prompt` fits R-001, R-217 and R-1194; `person` fits R-1014 and the desk rows. Default: `dot`.
- **D2 Age (lane B).** (a) Git: commits and whole days from the artifact's last commit to HEAD. (b) Plus the runtime map: commits from runtime-map-live's `tip` to HEAD. (c) Plus file times for untracked files, which a checkout resets. (d) Maker-written stamps for every artifact: right later, but lands, builds and reviews write no record yet. Age is counted to HEAD, never a clock, so the pinned byte-identical test holds. When it cannot tell, the report says why: "made each run", "no artifact named", "not tracked at HEAD", "no tip recorded", "tip not in HEAD's history". Recommend (b). Default: `git+tip`.
- **D2a Real reader.** The report shows the written reader and checks that each `code:` path is tracked. It links each path. Text-matching the reader's source for the artifact's name was rejected as false comfort. Default: `written`.
- **D3 Check placement.** (a) Only in the report, which nobody runs by habit (it missed 298 commits). (b) The tree checker command prints notes after its summary, exit unchanged; builders run `npm run req:tree` in every ledger lane, and other projects run `--root`. (c) The movement listing: its no-change output is pinned byte for byte. (d) One session-start line: the most live, but a hook lane. Recommend (b) now, the report in lane B, (d) later with the audit's hook queue. Default: `cli`.
- **D4 What it never does.** No note becomes a tree problem: a malformed line is a note, not a refusal. The suite never fails on a note, so a land never fails on one. Default: `notes`.
- **D5 Subtractions.** This lane: none in code. Lane B removes the derived consumer view, R-2452's consumer clause and the skill's "derived" sentence. The three rule lines (impact, movement listing, local install check) are each their output's only maker today; two are pinned by tests. Deleting them now loses the outputs. Recommend recording each as a `rule:` reader so the check lists it, and removing it in the lane that automates its maker. This changes the cost the owner approved, so it is his call. The measure step is gone with runtime-map-live. Default: `defer`.
- **D6 Split.** (a) One lane: it spans FEAT-028 and FEAT-039, and a lane is one feature. (b) Format and check with nana-pi's own lines (FEAT-028, two builds), then the report (FEAT-039). (c) Three lanes, as on 10-21. Recommend (b): the grammar meets real data before it lands. Other trees gain nothing until their owner adds `Kind: product`. Seeds stay kindless. The template text gains one sentence and ships with the next release tag. Default: `two`.
- **D7 Class.** Ordinary: scripts, tests, the ledger, skill and template text, as cap-kinds was. D3 (d) or a rule-line deletion would make it a hook or install lane. Default: `ordinary`.

## 5. Class, tunables, limits, threat, files, builds

**Class.** Ordinary (D7). The seat's wrong-code pairs come first: drop the reason test; check paths on disk instead of in git; read lines in feature spans; print notes on exit 1; render the lines in the outline; treat a second maker line as a note. Then one final reviewer of another lineage. Windows CI leg. Feature: FEAT-028 · Maintain requirement identity and trace links. Carry `requirements-moved.mjs` output in both briefs.

**Tunables** (exported from `scripts/deliverables.mjs`, beside its code as the tree checker keeps its labels; the R-2537 test pins the lists):
- `DELIVERABLE_FIELD_LABELS` ["Made by", "Read by"]: contract (the owner's 10-22 approval; R-2537).
- `MAKER_RUNS`: contract (R-2537). Source: the audit's six runs, plus hook and extension from the seat's brief, plus manual from the ruling.
- `READER_KINDS` ["code", "prompt", "person", "rule"]: contract (R-2537). Code and rule come from the ruling. Prompt and person are chosen, because injected context and pages a person reads are real readers but not code.
- `REASON_REQUIRED` [manual, rule, person]: contract (R-2535); person is chosen for the same reason as rule.
- `PART_SEPARATOR` " · ": chosen, the ledger's heading separator. `RUNTIME_MAP_ARTIFACT` "runtime-map": contract (R-2542). Age in commits and whole days: chosen (lane B).

**Known limits.** The check proves a reader path exists, not that it reads the artifact. Commands named in a reason or detail are not checked. The check itself is made by a hand-run command, so its notes reach only builders who regenerate the outline. A regroup that moves a deliverable's feature leaves its lines naming an unlisted row (one note each). Lane B: machine-local artifacts (journal, ledgers, knowledge index, handoff store) show "age unknown" until their makers record a tip. A shallow clone undercounts age. The three rule lines stay (D5).

**Threat model.** Honest variation is in scope. That covers a tree with no fields, a kindless or partly kinded tree, and a deliverable retired or homed elsewhere (R-2442 already refuses both; its lines become notes). It also covers a maker naming a command or path another project lacks (a note in that project only), Windows `\` paths and CRLF ledgers, and old committed outlines, which stay unchanged. Deliberate forgery is out: a line claiming `land` for a hand-made artifact, or a real path that never reads.

**Files.** New `scripts/deliverables.mjs` takes `parsed` and an injected tracked-path list. It imports nothing from the tree module, so it has no import cycle. `scripts/requirements-tree.mjs` main prints the notes. Also: the new test file; REQUIREMENTS.md (rows, 38 deliverables' lines, one sentence in "How this file is organized"); the requirements skill (grammar paragraph; pinned sentences stay word for word; no backticked path that rendered projects lack); `templates/_shared/requirements-organization.md` (one sentence, "capability → feature → subgroup" kept, R-1153); the README tree paragraph; regenerated map and outline; known-bug lines; HANDOFF; the session entry.

**Build sessions.** Build 1: R-2535 to R-2538, module, CLI and tests. Seat check: the pairs, then the check on a ledger copy carrying the seat's drafted lines. Build 2: R-2539 and the text. The 38 lines come from the audit's per-item table, which the seat puts in the lane folder with home paths written as ~ (the identity scan blocks them). The 8 desk and app rows get fresh research. Lane B starts after lane A and runtime-map-live land.
