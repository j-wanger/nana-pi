# rm-outside-asks: a plain rm outside the working folder asks first

Feature: FEAT-010 · Guard risky commands and protected resources

**Feature.** In pi's bash and PowerShell tools, a non-recursive delete (`rm x`, `rm -f x`, `Remove-Item x`) whose readable target lies outside the session working directory and outside every temp folder asks first and names that target; a target inside the working directory or a temp folder runs unasked, as today (owner rulings 2026-10-10 and 2026-10-20).

**Class: gate** (pi extension `extensions/nana-gate.ts`, new `lib/gate-rm-outside.ts`, three new exports from `lib/gate-shell.ts`). Ladder: roster reviewer, land reviewer (seat-land.md when the roster prints `land: seat`), seat wrong-code pairs, one independent check. The seat reads the Windows CI leg on the reviewed tip before the land, because the PowerShell and junction cases serve Windows first; that is the seat's choice for this lane, since the owner said on 2026-10-20 that not every land needs a green Windows leg. pi only: Claude Code has no nana command gate.
**Threat model.** In scope: honest variation in commands, paths, platforms and config: the spellings below, links and junctions, `/var` vs `/private/var`, 8.3 temp names, Git Bash. Out: deliberate forgery (eval, base64, a variable built to hide a path), a race that swaps a folder for a link after the check, a prefix, `BASH_ENV` or spawn hook that moves the cwd. The gate is advisory by load path.

## Design
- `lib/gate-rm-outside.ts` exports `rmOutsideTargets(segments, cwd, tool, { home, tempRoots, segmentable })`: a Map from segment to the full path of its first outside target. It never throws; an internal error counts the segment's own text as outside.
- Walk segments in order. Command word as `commandIndex(t, true)` finds it (skips assignments, `command`, `env`, `nohup`, `then`, `do`, `xargs`, `sudo`; `/bin/rm` and `\rm` are `rm`). Bash: `rm`. PowerShell: gate-shell's `PS_REMOVE` set.
- Targets: bash words not starting with `-`, and every word after `--`. `tokens(text, true)` splits `2>/dev/null` into `2` and `/dev/null`, so redirection operands (after `<`, `>`, `>>`, `2>`, `&>`, `>&`) and their fd numbers are found in the segment text and dropped. PowerShell: positional words and the value after `-Path`/`-LiteralPath` (and unambiguous prefixes); values after `-Filter`/`-Include`/`-Exclude` skipped; `\` is a separator; a comma list splits.
- Reading: a leading `~`, `$HOME`, `${HOME}` (PowerShell also `$env:USERPROFILE`, `$env:HOME`) is `home`. A target that begins with any other `$`, a backtick or `~user` is not judged. A glob (`*?[]{}`) or variable in a later part: the target is judged as a child of the literal folder before it.
- `cd`/`pushd` (PowerShell also `chdir`, `sl`, `Set-Location`, `Push-Location`): the first word after it that does not begin with `-` is the folder (so `cd -P ..` and `Set-Location -Path ..` read `..`); no folder word means home; a lone `-`, `popd` or a folder that begins with a variable leaves later relative targets unjudged. In a segmentable command a `cd` replaces the folder relative targets are judged from. In an unsegmentable one (subshell, group, heredoc) a `cd` adds its folder to the set, and a relative target asks when it lies outside judged from any of them.
- Place: `realPath` of the target's parent plus its last name, so a link on the way is followed and a last-part link is judged where it sits. Outside means not strictly inside `realPath(cwd)` and not strictly inside `realPath` of any temp root, tested on `path.relative`, never a string prefix.
- `commandHit`: after the floor loop and the in-folder exemption, run it over the exec segments, and separately over the detection segments of an unsegmentable command. A hit segment with no danger yet gets the non-floor danger `rm outside the working folder: <full path>`. Allow, extra, protected, cross-segment and verifier-pipe checks run after it, unchanged. `tempRoots` comes from the shared temp-root helper lane-guard-temp-root lands; this lane adds no temp rule of its own.

## Known limits
1. A target that begins with another variable, a command substitution or `~user`, or a relative target after an unreadable `cd`, is not judged: the computed-path class R-056 declares. Only the variable-led form is pinned (R-2337), because builders' cleanup relies on it.
2. A session started in home or a filesystem root sees nothing under it as outside.
3. Temp folders are shared: a plain rm of another session's file there (a reviewer checkout under `$TMPDIR`) runs unasked.
4. A glob or variable in a folder part is judged by the literal folder before it; a glob that matches a linked folder leading outside runs unasked. `..` after a linked folder is judged lexically.
5. In a command the gate can split, a `cd` applies to the rest of the line even when it fails or sits in a pipeline, so `cd sub/deep | true; rm ../../x` runs unasked. Inside a subshell or group a `cd` only adds a folder, which can only over-ask.
6. Command position only: `echo rm ../x` and `grep rm ../x` are not judged. `unlink`, bash `rmdir`, `mv` and a truncating redirect are not judged by place. Recursive and `--force` forms keep today's verdict and its unnamed reason. Heredoc lines that look like rm are judged.
7. Git Bash on Windows: `/tmp/…` and `/c/…` are judged as drive paths, so they ask even when they reach the temp folder.
8. PowerShell: colon-bound `-Path:x`, pipeline input, `-Filter`/`-Include` scope and backtick escapes are not read.
