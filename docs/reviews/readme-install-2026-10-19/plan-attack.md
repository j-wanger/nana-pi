# readme-install — plan attack (one adversary)

Verdict: AMEND

AMEND. The lane is worth building, but the plan as written would probably turn the blocking macOS install-check job red on its first CI run. It also has the wrong lane class.

1. CI break (inferred, high confidence). On the macos-26-arm64 runner, Node 24 and npm 11 are brew-linked into /opt/homebrew/bin. Homebrew's installer writes /etc/paths.d/homebrew. In `zsh -l`, path_helper puts that folder ahead of setup-node's toolcache; I reproduced this with a runner-like PATH. `nana-setup trust` finds pi through `npm root -g` (nana-setup.mjs:426). It would read Homebrew's root, which has no pi, and crash. My probe with an npm whose root lacks pi gave a stack trace and exit 1. The plan's most-likely-wrong claim named the Node version, not this. Fix: a home npm prefix (npm_config_prefix, with its bin ahead of PATH) stands in for step 1. Step 2 then runs as written into that prefix, so `npm root -g` and `pi` always match. Probe: every step exits 0, about 10 s in total, 6.5 s of it the real pi install.
2. Subtraction. The home prefix removes the machine-scope drop rule and the old R-1546, which duplicated R-1093 and R-951. It also removes the "a local run uses the machine's pi" limit. It closes a harm too: under the old rule, a reworded global install (`npm install -g`) would have written to the machine's npm prefix on a local seat run.
3. Class is ordinary, not install. The lane changes no install, uninstall or doctor code, hook, extension, gate policy or land or review tool. Earlier lanes set the precedent: fresh-install-2026-10-13 ("small, install-check output") and win-install-shape-2026-10-17 ("ordinary"). The AGENTS rule still applies: the seat runs install-check locally before nana-land. Added seat check: the pull request's macOS install-check job prints PASS readme checklist before the land. That is the only way to verify point 1.
4. Evidence fixes. The macOS CI run printed 13 result lines, not 14. Today's README passes the rehearsal as is, because doctor run from the home skips the trust check. So the `cd` row (now R-1546) is the one that makes doctor run from the clone. The leaf total is computed from the fresh tree (+7), not fixed at 1,265.
5. Rows are renumbered R-1540 to R-1546; R-1547 to R-1549 stay unused. The red-today claims hold: five tests are on an absent module or adapter, R-1540 has no such item, and R-1546's step 8 parses with no `cd`. The reworded README passes readme:check with 0 problems, and the four existing fresh-machine tests stay green (probed).
