# Plan: land-regen-both

Feature: FEAT-008 · Integrate and clean up reviewed changes

## Purpose

A fix that restores agreed behaviour. The 2026-11-02 ruling says a conflict only in the generated files the land contract names, rebuilt by their own generators, counts as no conflict. nana-land does that for a textual conflict, but refuses ("unsupported merge semantics: generated path docs/code-map.md changed on both sides") when both sides changed a generated file in separate hunks that git merges without a conflict (`packages/nana-pack/bin/nana-land.mjs:156-158`). On 2026-11-07 that refusal forced every waiting reduction lane through another merge, review and full CI run after each land (about 45 minutes each). This lane makes nana-land rebuild those generated files with their own generators in the both-sides case too, as it already does for conflicts, and land without new CI or review.

## Assumptions

- A1. The rebuild uses the existing conflict path's code (`regenerateTree` with `GENERATOR_CONTRACT`), run on git's merged tree for every generated path both sides changed; the result replaces git's textual merge of those files.
- A2. A generator that fails, times out, or leaves another file changed refuses the land, as the conflict path does.
- A3. A both-sides change to any file outside the generator contract keeps its current handling (a textual conflict refuses; a clean merge of a non-generated file lands as today).
- A4. The 2026-11-02 ruling's sentence is reworded to cover a generated file changed on both sides, not only a conflict in one, in the same change.
- A5. One reviewer plus CI. This changes the land tool, so the local macOS install check runs before the land.

## Open choices

- O1. Builder decides whether to rebuild every contract path on any both-sides change or only the ones both sides touched, following the conflict path.

Honest variation in generator output and git merge results. Forgery out.

## Must-meet

- M1 (both sides, separate hunks). When the lane and main each changed `docs/code-map.md` (or `docs/requirements-tree.md`) in separate hunks with no textual conflict, nana-land lands with that file equal to its generator's output on the merged tree, and runs no new CI or review.
- M2 (generator failure). If that generator fails, times out or changes any other file, nana-land refuses and main is unchanged.
- M3 (other files unchanged). A both-sides textual conflict in a file outside the generator contract still refuses; a both-sides clean change to such a file still lands as today.
- M4 (conflict path kept). The existing generated-file conflict cases pass unchanged.
- M5 (ruling). The 2026-11-02 ruling covers a generated file changed on both sides and rebuilt by its generator, and the rule tests that pin its wording are updated with their rows.
- M6 (adversary 1: mixed). One generated file conflicts while the other changes cleanly on both sides: nana-land lands, both outputs equal independent generator runs, non-generated content is unchanged, and no suite runs.
- M7 (adversary 2: the old refusal test). `packages/nana-pack/tests/land-clean-merge.test.mjs:124-131`, which requires separate-hunk generated changes to refuse, is replaced by cases that exercise both contract paths with real generators and pin successful lands and exact regenerated bytes; the contract-path assertion stays, and the whole clean-merge test file passes.
